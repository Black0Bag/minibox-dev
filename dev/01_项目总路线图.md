# minibox 项目总路线图（纯净版）

> 版本：v2.0 纯净基线 ｜ 创建：2026-08-07 ｜ 定位：**本项目唯一最高基准**，一切开发以此为准。

## 1. 项目定位（一句话）

> **一个以 Go 后端为「中枢大脑」、以安卓 APP 为「眼耳口手」的私有化强 Agent 系统。**
> 后端通过云端 LLM 在本地执行长程任务（to-do-list + subagent 并行）；
> 以「知识库 = 唯一记忆」实现自我进化与用户蒸馏；
> 前端 APP 作为分离大前端，通过协议完整承接后端能力，并用无障碍 + Shizuku 把手机变成后端可操控的终端，用内嵌浏览器补齐后端的网页能力。
>
> **项目将开源发布（GitHub）**，面向未知设备环境，用户预期终身使用。

┌────────────────────────────────────────────────────────────────┐
│  Go 后端 minibox（中枢大脑，跨平台: 路由器/N1/云/PC，资源自适应）     │

**架构铁律**：整个项目**只有一个后端服务作为中枢**，后端无任何前端（含 CLI 高级功能）；其他所有端（安卓 APP、未来 PC）全部是前端，与单后端交互。

## 3. 核心设计理念（四根支柱）

### 支柱一：知识库 = 唯一记忆（铁律）
- agent 的**所有信息一律以知识库方式存放**，包括记忆/SOUL/画像等，全部入库（文本 + 向量双存储）。
- 分层是组织方式，知识库是唯一存储容器。
- 存储：SQLite 单文件（`modernc.org/sqlite` 纯 Go，零 CGO），FTS5 全文 + sqlite-vec 向量 + RRF 融合检索。
- 对外通过 MCP 服务接口暴露，供其他 agent 调取。

### 支柱二：权限三层级 + 确认通道只在自家界面
- **人类直接操作 > 代码级防火墙 > agent 自主决策**。
- 时间戳滚动文档设置底层防火墙，阻止 LLM 删改已记录文本（只能追加带时间戳条目）；用户可越过。
- 第三方 MCP 需授权的操作，后端**不执行**，而是推送到用户自己的 APP 确认界面，用户点「允许」才执行——第三方永远无法代替确认。

### 支柱三：logme 文件夹足迹系统（代码级）
- agent 读写/遍历某文件夹前，先检索该文件夹的 `logme` 文档：无则创建（写入用途/技巧/注意事项语义区），有则追加操作记录（时间戳 + 全局序号 + 操作者 + 动作）。
- **代码级 enforce**：所有文件操作经过 `fsutil` wrapper，只允许追加、禁止删改已有文本（用户授权例外 + 审计留痕）。

### 支柱四：时间戳机制全局化
- 除用户在对话框的任务外，agent 自主生成的一切记录性内容都以**时间戳滚动追加**方式记录。
- 时间戳格式统一 `YYYY-MM-DD HH:MM:SS`（真实时钟，NTP 校准）；全局单调递增序号（数据库自增主键）保证跨设备排序唯一。
- 知识库双区制：**缓存区**（临时记录，随时可清）+ **存储区**（正式文件，编译沉淀）+ 版本快照回滚（GitHub 式历史版本，一键回滚）。

## 4. 已定核心决策（汇总）

| 编号 | 决策点 | 结论 |
|---|---|---|
| A1 | 部署形态 | 跨平台 + 开源，资源自适应 + 向导式配置 |
| A2 | 知识库规模 | 终身使用：格式稳定、可迁移备份、schema 版本管理 |
| B1 | 记忆存储 | 知识库 = 唯一记忆（铁律），一切信息入库 |
| B2 | 存储选型 | SQLite + FTS5 + sqlite-vec 向量（已验证纯 Go 可行） |
| B3 | 进化/蒸馏 | 全部做成用户自定义设置项 |
| C1 | Agent 引擎 | 继续自研重构，不引大框架 |
| C2 | subagent | 并发上限/隔离/权限 → 用户自定义设置 |
| D1 | logme 内容 | 操作留痕 + 文件夹语义（用途/技巧/注意事项）都要 |
| D2 | logme 权限 | agent 只可追加（带时间戳），删改仅限用户授权 |
| D3 | 任务追踪文件 | 不采用，由 logme + 知识库统一替代 |
| E1 | 前端技术栈 | Kotlin + Compose（实际仓库已确认；路线图早期 Flutter 表述作废） |
| E2 | 协议 | 不限形式，稳定第一：WS+SSE+REST + 重连/保活/确认 |
| E3 | 语音 | 预留接口：本地 TTS 兜底，模型 API 后接 |
| E4 | 记事本编译 | 用户设定时间触发，结果存知识库 |
| F1 | 危险操作 | 逐次确认 + 白名单自动放行并存，用户可配 |
| F2 | 心跳任务 | 可主动操作，但必须绑定用户预设需求边界 |
| F3 | 备份方案 | 两层足够：后端本地快照 + 前端设备拉取加密快照；前端只存不读 |
| F4 | 升级方案 | Agent 智能化升级（自主下载/镜像加速/校验/PID/脚本回滚），非依赖外部库 |

## 6. 开发路线图（总览）

```
Phase 0（地基）     logme 系统 + fsutil wrapper + 时间戳组件（零阻塞，可立即开工）
Phase 1（大脑）     知识库编译管道 + 双区制 + sqlite-vec 落地 + Layer1 补全
Phase 2（并行）     Agent 引擎重构 + Model Normalizer + subagent（先 2 层）
Phase 3（四肢）     设备代理链路 + 性能监控 API + 四级降级
Phase 4（自动化）   心跳调度中枢 + 蒸馏/精炼 + Skill 沉淀闭环
Phase 5（数据安全） 备份系统 + 自升级（Agent 智能化 + watchdog）
Phase 6（开源）     文档/向导/安全默认值/多平台构建
```

- 前端按 `F0 协议地基 → F1 聊天内核 → F2 知识库 → F3 设备控制 → F4 通知 → F5 设置/备份 → F6 扩展 → F7 PC 占位` 与后端 Phase 对齐推进。
- 详细任务拆分见 `02_后端开发路线图.md` 与 `03_前端开发路线图.md`。

## 7. 全局注意事项（红线，必读）

1. **中文优先**：所有非机器语言（注释/配置/CLI/API/文档/错误信息）一律简体中文；Go 关键字与库名保持英文。
2. **零 CGO 硬约束**：所有依赖必须纯 Go（交叉编译 `CGO_ENABLED=0`），任何引入 CGO 的库都要拒绝。
3. **端口统一 8086**（REST+WS+SSE 统一入口，可配置可覆盖），前端连接地址 `http://<ip>:8086`。
4. **版本号单一来源**：只在一个地方定义 `Version`，其他位置引用（踩过双变量坑）。
5. **前端永不直接访问数据库**：一切数据操作经后端 API；仅 SSH/SFTP 两个直连例外。
6. **前端不承担数据副本**：备份以「后端 → 前端」单向为主，前端只存加密快照。
7. **TDD 优先**：每个功能先写失败测试 → 实现 → 通过 → 提交（superpowers 方法论）。
8. **提交前自查**：`go vet` / `go test ./...` / `golangci-lint`（CI 已自动跑，本地无 Go 则靠 push 触发）。
9. **文档滚动追加原则**：本仓库既有文档只允许末尾追加带时间戳条目，不删改已有内容（与项目理念一致）。
