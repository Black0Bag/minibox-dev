# minibox 项目总路线图

## 一句话定位

minibox 是一个以 Go 后端为中枢、以 Android APP 为用户界面和设备执行端的私有化强 Agent 系统。

## 系统边界

```text
Android APP（UI + 设备能力）
        │ REST / SSE / WebSocket JSON-RPC
        ▼
Go 后端（Agent + LLM + 知识库 + 工具 + 调度）
        │
        ├── SQLite / FTS5 / 向量
        └── OpenAI 兼容 LLM / Embedding
```

- 后端拥有业务状态、模型路由、知识库和权限策略。
- 前端拥有交互状态、安全存储、网络连接和设备执行能力。
- 前端不直接访问后端 SQLite，不在本地复制 Agent/LLM 编排。

## 核心产品原则

1. **知识库是后端统一记忆容器**：SQLite、FTS5、向量和结构化编译由后端管理。
2. **权限分层**：用户决定 > 代码级护栏 > Agent 决策；危险写操作 fail-closed。
3. **三通道分工**：REST 管状态与命令，SSE 管 Agent/系统事件，WebSocket 管设备双向 RPC。
4. **可审计**：工具、设备命令、事件和错误使用关联 ID，不用 HTTP 200 掩盖业务失败。
5. **私有优先**：默认监听 loopback，凭据不进 Git，前端不得泄露屏幕/剪贴板/令牌。

## 当前实现事实

- 后端技术栈：Go 1.26.6、Chi、modernc SQLite、koanf、coder/websocket、robfig/cron。
- 后端支持多供应商 LLM、Embedding、Agent 状态机、知识编译/蒸馏、设备 Hub、调度、备份和监控。
- 18 个设备工具已接入 Agent 工具注册表；写操作需要审批。
- SSE 支持有限历史和 `Last-Event-ID`；WebSocket 采用单读循环和 pending map。
- REST 全端点 Bearer Token 认证（含 SSE 流），错误统一 RFC 9457 Problem Details。
- Agent 审批可由前端提交（`POST /api/v1/approvals/{run_id}`）。
- CI 四 job 全绿（测试 / Linux x86_64 竞态 / golangci-lint / 依赖审计）。

## 下一阶段路线

1. 建立 Android Compose/Navigation 3 工程和连接诊断（后端契约已冻结，可开工）。
2. 完成会话 + SSE 主流程，再实现设备代理。
3. 补齐仍在内存的状态（团队项目、SSE 历史、编译作业）或明确重启语义。
4. 实装浏览器代理链路（前端 WebView 执行 + 后端 Agent 工具与下发路径）。
5. 择时生成 OpenAPI 以消除手写 DTO 漂移。
6. 真实设备副作用和高风险功能逐项授权验收。
