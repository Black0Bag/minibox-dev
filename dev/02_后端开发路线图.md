# minibox 后端维护路线图

## 当前结论

后端核心阶段完成，已通过全仓 `go test -count=1 ./...`、`go vet ./...`、构建和隔离实例冒烟。后端不再以“继续补齐所有规划功能”为主，而以**稳定契约、安全加固和前端阻塞修复**为主。

## 已完成能力

- 多供应商 OpenAI 兼容 LLM、功能级模型路由和供应商降级。
- Embedding query/passage、维度校验和语义/全文混合检索。
- SQLite 迁移、FTS5 中文预分词、向量、编译、蒸馏和快照。
- Agent 状态机、MemoryGate、Plan-first、工具权限和运行持久化。
- REST、SSE 断线回放、WebSocket JSON-RPC 单读循环和乱序回执。
- 设备 Hub、审计、护栏和 18 个设备工具。
- 调度、团队协作、监控、备份、升级机制和首次向导。

## 前端开发前的后端待办

| 优先级 | 事项 | 原因 |
|---|---|---|
| P0 | 决定并实现非 loopback REST 认证 | Android 跨设备连接不能只依赖 loopback 安全默认 |
| P0 | 审批 API 契约 | 当前会话流程收到审批事件后自动拒绝，没有前端提交入口 |
| P0 | 修复/冻结团队 `TaskDependency` JSON tag | 避免 Android DTO 不可预测 |
| P1 | OpenAPI 契约 | 减少手写 DTO 漂移；先确认首版范围 |
| P1 | 明确重启持久化范围 | 会话、团队项目、SSE 历史等部分状态在内存中 |
| P1 | Linux x86_64 race CI | 当前 Android/arm64 环境无法运行 ThreadSanitizer |
| P2 | 分拆大型 app handler 文件 | 降低维护冲突，不改变接口 |

## 维护门禁

```bash
gofmt -l internal
go test -count=1 ./...
go vet ./...
go build ./cmd/minibox/
```

- LLM/Embedding 改动先做 HTTP fixture，再做真实供应商探针。
- 数据库改动先在新测试库跑迁移、回填和 CRUD。
- WS 改动必须保留单读循环并跑并发乱序响应测试。
- SSE 改动必须跑 HTTP `Last-Event-ID` 重连测试。

## 不在普通维护中执行

- 真实 Android 点击、输入、通知、剪贴板等副作用。
- 自升级真实替换稳定二进制。
- 主数据库恢复或覆盖。
- 外部平台写入和正式发布。

这些操作都需要独立授权、备份和回滚计划。
