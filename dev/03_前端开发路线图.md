# minibox Android 前端开发路线图

## 技术基线

- Kotlin + Jetpack Compose + Material 3。
- Navigation 3：可序列化 `NavKey`、`rememberNavBackStack`、`NavDisplay`。
- 单向数据流：ViewModel 持有 `StateFlow<UiState>`，Composable 状态下沉、事件上行。
- REST/SSE/WebSocket 三个客户端分离，共用统一 Envelope/Problem DTO。
- Android Keystore/加密存储保存设备凭据；不保存后端 LLM API Key。

## F0：协议与工程地基

1. 创建 Gradle Version Catalog、app 模块、Compose 主题、测试目录。
2. 建立 `core:model`：Envelope、ProblemDetail、Session、Message、Device 等 DTO。
3. 建立 REST 客户端和错误映射；集合路径保留尾斜杠。
4. 建立 SSE 客户端：单 session 单连接、seq 去重、Last-Event-ID、退避重连。
5. 建立 WS 客户端：单读循环、唯一 ID、pending map、握手/心跳/重连。
6. 用 `/health`、`/ready`、`/server/status` 完成连接诊断页。

## F1：会话与 Agent 状态

- 会话列表、创建、详情、发送消息、回退。
- SSE reducer 处理运行开始/步骤/完成/失败、用户/助手消息和审批事件。
- 消息发送期间显示可取消加载状态；错误显示为错误，不写入助手正文。
- 当前审批事件只可展示“后端自动拒绝并换方案”；后端开放审批提交 API 后再增加允许/拒绝按钮。

## F2：知识库

- 搜索、分页列表、条目查看/编辑。
- 编译提交与作业轮询；展示 LLM 提炼/Embedding 降级状态。
- 快照列表可读；回滚属于高风险，首版隐藏或只读。

## F3：设备代理

- 前台服务持有 WebSocket；握手后上报 `device`/`hello`。
- 实现 18 项能力对应的 Android 执行器，但按权限与能力逐步启用。
- 读操作和写操作分层；写操作显示目标设备、动作摘要和权限状态。
- 截图、剪贴板、通知和语音数据不得进入普通日志。
- 真实副作用按能力逐项授权测试。

## F4：管理页面

- 工具与风险元数据、权限模式、LLM provider/model、功能级模型。
- 监控指标和历史；使用生命周期感知采集，不在后台高频轮询。
- 调度任务、团队分诊和项目状态。
- 升级/恢复在 REST 认证与运营审批补齐前不提供执行按钮。

## 导航结构

推荐顶层：会话、知识、设备、管理。每个顶层保留独立 back stack；详情页用可序列化 ID 路由，不把大对象塞进路由。

## Compose 规则

- 公共 Composable 使用 `modifier: Modifier = Modifier` 并应用到根布局。
- Screen 从 ViewModel `collectAsStateWithLifecycle()`，内容 Composable 保持无状态。
- 共享组件提供 Light/Dark Preview。
- 固定工具栏、设备状态和列表项尺寸，避免动态文本导致布局跳动。

## 无障碍门禁

- 所有操作目标至少 48×48dp。
- 可点击 Icon 描述动作；纯装饰图标 `contentDescription = null`。
- 标题加 heading 语义；复杂列表项合并语义。
- 连接、选中、审批、错误提供 `stateDescription` 或等价标准语义。
- 验证字体放大、TalkBack、深色模式、横屏和窄屏。

## 验收顺序

Mock REST/SSE/WS → 后端稳定实例 → 模拟设备 → 单独授权的真实设备能力。每阶段保留可复现测试，不把真实副作用作为普通 CI。
