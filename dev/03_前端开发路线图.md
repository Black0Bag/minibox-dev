## 0. 前端定位与技术栈

**定位**：分离大前端——纯 UI 客户端，AI 能力全由后端提供；作为后端的「眼耳口手」终端。

| 维度 | 约束 |
|---|---|
| 技术栈 | **Kotlin + Jetpack Compose + Material 3 Expressive**（实际仓库已确认；早期 Flutter 表述作废） |
| 架构 | Presentation / Domain / Data 三层；MVVM/MVI + UDF（单 UiState 密封类） |
| 网络 | Retrofit + OkHttp（REST）+ SSE（okhttp-eventsource）+ WebSocket |
| 本地 | Room（会话/草稿）+ DataStore（偏好） |
| DI | Hilt |
| 直连例外 | 内置 SSH/SFTP 客户端直连后端（不走 API） |
| 铁律 | **前端永不直接访问数据库文件**，一切数据操作经后端 API |

## 1. 开发路线图

### Phase F0 协议地基（🔴 最先）

**目标**：与后端稳定通信的协议层。

| 任务 | 说明 |
|---|---|
| REST API 客户端 | 封装后端全部 API，统一 `/api/v1` 前缀 + RFC 7807 错误映射 |
| WebSocket 长连接 | 断线重连、心跳保活、消息确认（coder/websocket 同款机制） |
| SSE 事件流客户端 | 接收统一事件（thinking/answer/tool/context_meta），断线续传（seq 记忆） |
| 协议版本协商 | 握手交换 protocol_version，旧版兼容新版提示 |
| 前端能力声明 | 连接上报：浏览器可用/Shizuku/无障碍/存储/电量/网络/备份配置 |
| 前端 ID 注册 | 多前端自带 ID，接入被记录 |

### Phase F1 聊天内核：所见即所得

**目标**：完整聊天渲染与交互。

| 任务 | 说明 |
|---|---|
| SSE 渲染引擎 | 按 renderSource 路由卡片（thinking 卡/answer 卡/tool 卡） |
| 逐字流式 | token 级逐字追加 + 增量 Markdown 状态机（代码块/表格保持打开态） |
| 断线续传 | 记 seq，重连从 seq+1 重放 |
| 思考折叠卡 | 默认折叠可展开，持久留痕，不计入上下文 |
| 可审计视图 | 历史截断/摘要/工具注入/系统提示明细，默认折叠点开才看 |
| 输入框交互 | 跟随键盘；回车=换行；单行→扩展(max 1/3屏)→内部滚动；草稿持久化；发送键/停止键切换 |
| 附件输入 | 图片+任意文件，粘贴板预览，3×3 宫格上限 9 |
| 消息气泡 | 用户右/AI 左；AI 侧显示模型图标；时间分隔条；连续 AI 消息合并块 |
| 长按菜单 | 复制/删除/编辑/重试/回退；编辑后旧回复灰显「已编辑·已过期」；保留痕迹可审计 |
| DTO 同源 | 前端展示与后端持久化共用同一 messageId+text |

### Phase F2 知识库前端

**目标**：展示与编辑知识库，一切经后端 API。

- 知识库浏览器（分层查看/搜索）
- 条目编辑器（经 API）
- 编译管道任务管理（SSE 进度：编译中/已暂停/完成）
- 专属控制界面（蒸馏关键词+概率，独立条目可单独删改；REST 全量 + SSE 增量）
- 版本管理 UI（浏览快照/一键回滚/可选填原因）

### Phase F3 设备控制层

**目标**：让后端通过 APP 操控手机 + 内嵌浏览器代理。

| 任务 | 说明 |
|---|---|
| 无障碍服务 | 截屏、点击、滑动、输入、通知读取 |
| Shizuku 集成 | ADB 级能力：完整文件管理/系统定制/自动化脚本 |
| 设备代理 WS 客户端 | 接收后端「设备_*」method，执行回传 |
| 危险操作确认弹窗 | 后端推确认 → 弹窗（摘要/影响/可回滚）→ 用户确认 → 回传 |
| 授权确认通道 | auth.request → 弹窗 → auth.response（带设备签名） |
| 内嵌浏览器 WebView | 供后端远程使用，subagent 独立标签页 |
| 浏览器_* 工具集 | 打开/前进/后退/刷新/查找/点击/输入/滚动/截图/取文本/提取正文 Markdown |
| 正文提取 | WebView 渲染 → DOM → Readability → 干净 Markdown → 回传 |
| Tab 管理 | 每 subagent 独立 tab，任务结束可配关闭/保留 |
| 截图像素级模糊 | 隐私保护 |
| MacroDroid 智能化 | 触发器=手机全事件；动作=agent 下发行为；条件=专属心跳监控 |

### Phase F4 通知与在线状态

| 任务 | 说明 |

### Phase F5 备份与设置

- 备份配置页（时间/位置/留存数/运营商数据开关/电量阈值/手动触发/加密密码/恢复入口）
- 备份执行：前端发指令 → 后端生成加密快照 → WS 推前端 → **前端只存不读**
- 备份恢复：选快照 → 推回后端 → 后端验证恢复
- 通用设置页（LLM 供应商/模型/进化策略/安全策略/subagent 配额）
- 模型分配管理页（8 项功能级模型独立配置；Key 脱敏显示 + 显示全部）
- 对话参数控制（思考强度 5 档/温度/TopP/最大Token/频率惩罚/存在惩罚/停止序列/自定义系统提示词）
- 后端升级管理（检查/触发/日志/回滚；升级中转连 watchdog 看真实进度；SMTP 配置页）

### Phase F6 扩展体验

- 记事本 + 编译触发（条目状态：待编译/编译中/已编译/失败）
- 桌面小组件（快捷入口 + 状态展示）
- 语音层预留（本地 TTS 兜底 + 模型 API 接口位）
- SSH / SFTP 客户端（直连后端，不走 API）
- P2P 前端互联（后端做红娘 → 局域网直连 → 降级中转兜底）
- 后端版本管理（前端视角可独立管理版本）

### Phase F7 PC 端占位

- 同一协议层复用（Web/Electron），本轮不展开
- PC 端驱动级控制（未来方向，风险后续讨论）

## 4. 前端注意事项（红线）

1. **Compose 关键规则**：edge-to-edge + Scaffold padding；`collectAsStateWithLifecycle`（禁 collectAsState）；LazyColumn 稳定 key；MVI 单 UiState 密封类；无逻辑在组合函数体。
2. **UI 文案**：一律简体中文，不硬编码英文。
3. **状态管理**：StateFlow/SharedFlow（一次性事件用 SharedFlow），结构化并发 viewModelScope。
4. **API 对齐**：前后端任何 API 变更必须同步更新对齐文档；`/api/v1` 前缀两端一致。
5. **超时**：前端 HTTP 客户端超时略大于后端（+5s）；429 按 Retry-After 重试。
6. **安全**：API Key 只存后端，前端不存密钥；截图默认降采样 + 敏感区域模糊。
7. **浏览器**：每个 subagent 独立 tab 互不抢占；正文提取在前端 WebView 完成（后端零负担）。
8. **通知**：防刷屏（去重/限流/静默）；任务级合并（一次对话=一条通知）。
9. **前端不碰数据库**：SSH/SFTP 两个直连例外之外，一律经后端 API。

## 5. 决策确认记录（滚动追加）

### logme 跨前端传播 — ✅ 已确认（2026-08-08）

**来源**：后端 Q-08 决策确认，涉及前后端交叉修改。

**前端落地要求**：
- 前端 APP 在手机上进行文件浏览/操作时，同样需生成 logme 文件
- **F3 设备控制阶段**需落地：无障碍+Shizuku 执行文件操作时，自动生成 logme（含时间戳+操作记录+文件快照 mtime）
- logme 格式与后端保持一致（时间戳滚动追加 + 全局序号）
- logme 是可丢弃缓存，过期（mtime 校验不通过）时由前端重新遍历覆盖写

**前后端 logme 一致性**：
- 格式统一：时间戳 + 全局序号 + 操作者 + 动作 + 文件快照
- 行为统一：只追加不删改（用户授权例外）、mtime 过期检测
- 存储分离：前端 logme 存在手机本地被操作文件夹内，后端 logme 存在服务器被操作文件夹内

### 事件体系统一化（前后端交叉） — ✅ 已确认（2026-08-08）

**来源**：后端 Q-06 决策确认，涉及前端 F0 协议地基。

**前端落地要求**：
- **F0 协议地基阶段**直接采用统一信封格式，不写三套独立解析逻辑
- 前端解析器只需实现一套：读取 spec_version / event_id / trace_id / timestamp / producer / type / data
- 根据 type 前缀分派处理：`api.*` → REST 响应、`agent.*` → SSE 对话流、`device.*` → WS 设备控制
- event_id 用于去重（幂等性），trace_id 用于跨通道任务追踪展示
- spec_version 用于版本兼容判断（收到不支持的版本时提示用户升级前端）

**时间戳机制同步**：
- 前端收到的事件信封中 timestamp 与后端"时间戳全局序号"机制统一
- 前端展示事件时统一使用信封中的 timestamp，不再自行生成时间戳
