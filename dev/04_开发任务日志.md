| `internal/fsutil` | 文件操作 wrapper（统一入口）+ logme 留痕 + 防火墙（WriteNew 防覆盖、Append 只追加）+ 全局单调序号（持久化）+ 敏感信息脱敏 |

| `cmd/minibox` | CLI（配置/启动/状态）；优雅关停（30s，N-01）；版本单一来源（ldflags 注入） |

### 测试与验证
- 单元测试：5 个包全部通过（logging/config/fsutil/timestamp/api）
- golangci-lint：本地全绿（先本地修再推 CI）
- CI：Quality Check（vet+test+lint）+ Build and Release 均 success
- 本地真实运行：健康检查/状态/供应商 CRUD/日志查询/脱敏全部通过
- 真实 LLM API 连通性验证（cheapapi + zen 均可调用）

### 遇到的问题与修复（关键记录）
1. **`ParseLevel` 大小写 bug**：slog 的 `Level.String()` 返回大写（"ERROR"），导致日志查询解析失败返回 0 条。修复：`ParseLevel` 对输入 `strings.ToLower`。
2. **`config.Provider` JSON 解码 bug**：只有 yaml tag 没有 json tag，`api_key`/`base_url` 字段 JSON 解码失败（key 显示为 `***`）。修复：补 json tag。
3. **golangci-lint errcheck**：`file.Close()` 返回值未检查（2 处 fsutil + 2 处 logme）。修复：显式处理 Close 错误，去除 `defer Close`。
4. **golangci-lint staticcheck 弃用**：`middleware.RealIP`、`httprate.LimitByIP`、`Limit`、`KeyByIP` 均已弃用。修复：移除 RealIP；改用 `httprate.LimitBy` + 自定义 `ipKey`（注意 KeyFunc 签名是 `(string, error)`，非命名类型转换）。
5. **.gitignore 误伤 `internal/api`**：`api` 规则匹配任意层级，把 `internal/api/` 目录也排除了，导致 API 代码没提交。修复：改为 `/api`（仅根目录）。
6. **CI 版本提取 bug**：release.yml 用 `grep 'var Version'` 提取版本，永远拿到 main.go 默认值 "dev"，导致 v0.1.0 二进制命名 `minibox-dev-*` 且运行时版本显示 dev。修复：改为 `git describe --tags --abbrev=0` 优先取 tag；删除旧 v0.1.0 tag/release 后重新发布。
7. **gh run download 卡住**：artifact 下载超时。改用 gh API 拿下载链接 / 直接从 dev Release 下载，成功。
8. **中文路由**：curl 命令行直接请求 `/状态` 返回 404——因 HTTP 规范要求 URL 编码。前端 HTTP 客户端自动编码，实际使用无问题（已用 URL 编码验证全通）。

### 发布结果
- **v0.1.0 正式 Release**（非 prerelease）：`minibox-0.1.0-linux-amd64` / `-arm64` / `-windows-amd64.exe` + `checksums.sha256`
- 运行时版本验证：`minibox version 0.1.0` ✅
- 本地运行验证：健康检查/状态正常 ✅

| API | 知识库 写入/读取/列表/搜索/更新/删除/清空（中文路由） |

### 验证结果
