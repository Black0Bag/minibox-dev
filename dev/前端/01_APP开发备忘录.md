# Android APP 产品备忘录

## 产品定位

- Android APP 是 minibox 的用户界面和设备侧执行器，不承载 LLM/Agent/SQLite 业务内核。
- 后端是大脑；APP 是眼耳口手，通过 REST、SSE、WebSocket 协作。
- 首版以连接稳定、会话、流式状态和设备代理为核心，不复制旧应用的终端/proot 体系。

## 首版核心体验

### 连接与诊断

用户配置后端地址和设备凭据，APP 显示：连接中、后端就绪、LLM/数据库/向导检查、WS 设备状态和重连原因。

### 会话

- 创建、列表、详情、发送消息和回退。
- 运行状态由 SSE 驱动，不用高频轮询。
- 发送消息是异步的：接口返回 `run_id`，回答走 SSE。
- Agent 错误以错误状态展示，不能伪装成助手回答。
- 审批事件可做真实允许/拒绝按钮（后端审批提交 API 已就绪），
  运行终态后收起审批 UI。

### 设备

- 眼：截屏、UI 层级、通知、设备信息、前台应用等。
- 手：点击、滑动、长按、输入、按键、打开应用、滚动查找。
- 口：朗读、提示、通知。
- 耳：听写、监听。
- 写操作必须清楚展示动作、目标和审批状态。

### 知识与管理

知识搜索/条目/编译状态是首版扩展；调度、团队、监控随后接入。升级和数据库回滚在认证与运营审批补齐前不提供执行入口。

## 交互原则

- 工作型界面：安静、密度适中、可扫描，不做营销式首页。
- 首屏直接进入连接状态或会话，不做功能介绍卡片。
- 常用命令使用图标按钮并提供 tooltip/无障碍描述。
- 不嵌套卡片，不用大圆角装饰，不用单一紫色/深蓝色主题统治界面。
- 文本可换行，不遮挡工具栏、状态条或输入框。

## 消息交互

后端当前 rewind 接口只接收 `keep` 数量，不支持旧方案里的多轮后悔快照和 `rewind_to_message_id`。首版按真实接口实现简单回退；复杂历史编辑等后端契约明确后再设计。

Todo 当前是 Agent 工具/Run 内状态，没有稳定公开的会话 Todo REST/SSE 契约。首版不实现虚假的 Todo 悬浮条，等后端事件契约补齐。

## 本地数据

前端只缓存：服务器地址、非敏感偏好、草稿、必要的离线 UI 状态和最后 SSE 序号。后端会话/知识以服务端为准；设备凭据进入安全存储。

## 验收底线

- TalkBack 可完成连接、发消息和查看错误。
- 字体放大后输入框、消息、按钮不重叠。
- 所有可点击目标至少 48dp。
- 断网恢复不重复消息或错误归属 WS 响应。
- 日志不包含凭据、屏幕、剪贴板和完整用户内容。
