## 一、解绑 proot：纯前端架构分析

### 1.1 小万源码依赖拓扑图

小万 OmniBot 有 6 个顶层模块，其中只有 **ReTerminal** 和 **app/terminal/** 是 proot 核心依赖：

```
OmniBot/
├── ui/          ← Flutter UI（407 Dart） — 纯前端，但有 terminal 引用
│   ├── lib/features/home/pages/chat/     ← 聊天核心（含 chat_page_terminal_env.dart）
│   ├── lib/features/home/pages/command_overlay/  ← 消息渲染引擎（纯 UI）
│   ├── lib/features/home/pages/settings/ ← 设置页面（纯 UI）
│   ├── lib/features/memory/              ← 记忆中心（纯 UI）
│   ├── lib/features/welcome/             ← 引导流程（含 onboarding_environment_controller）
│   ├── lib/services/chat_terminal_environment_service.dart  ← ⚠ terminal 依赖
│   └── lib/widgets/embedded_terminal_init_overlay.dart      ← ⚠ terminal 依赖
├── app/         ← Kotlin Host（414 kt）— Agent 引擎 + 工具系统
│   ├── agent/runtime/         ← Agent 编排（含 AgentTerminalDistributionText.kt）
│   ├── agent/tool/handlers/   ← 工具处理器（TerminalToolHandler.kt ⚠）
│   ├── terminal/              ← ⚠ 嵌入式终端全部文件（8 个 kt）
│   ├── termux/                ← ⚠ Termux 命令执行（1 kt）
│   ├── mcp/                   ← MCP 服务（纯后端，不依赖 terminal）
│   ├── agent/tool/alarm/      ← 闹钟工具（纯）
│   ├── agent/tool/calendar/   ← 日历工具（纯）
│   ├── agent/tool/music/      ← 音乐工具（纯）
│   ├── agent/workspace/       ← 工作区管理（纯）
│   └── ui/channel/            ← Flutter Platform Channel（大部分纯）
├── ReTerminal/  ← ⚠ 整个模块是 proot 终端实现（不动）
├── webchat/     ← React WebUI（19 tsx/ts）— 纯前端
├── uikit/       ← 悬浮球/覆盖面板 — 纯 Native UI
├── assists/     ← 辅助功能库
└── baselib/     ← 基础库
```

| 模块 | 文件数 | 职责 | 处置 |

| `app/.../terminal/` | 8 kt | 嵌入式终端生命周期管理（启动/初始化/会话注册） | ❌ 完全移除 |
| `app/.../termux/` | 1 kt | Termux 命令执行器 | ❌ 完全移除 |
| `app/.../operit/terminal/` | 7 kt | Operit 遗留终端管理（TerminalManager/FileSystemProvider 等） | ❌ 完全移除 |

| `chat_page_terminal_env.dart` | 移除 chat_page 中的 terminal 环境 mixin |

### 1.4 纯前端架构方案

minibox 2.0 前端 APP 的定位：**纯 HTTP 客户端**，所有 AI 能力由后端提供。

```
┌───────────────────────────────────────┐
│  minibox APP（纯前端）                  │
│                                       │
│  ┌─────────────────────────────────┐  │
│  │  UI 层（Jetpack Compose）         │  │
│  │  - 聊天界面                       │  │
│  │  - 会话管理                       │  │
│  │  - 设置                          │  │
│  │  - 记忆浏览                       │  │
│  │  - 定时任务                       │  │
│  │  - 引导流程                       │  │
│  └──────────┬──────────────────────┘  │
│             │ HTTP + SSE              │
│  ┌──────────▼──────────────────────┐  │
│  │  数据层（Retrofit + OkHttp）      │  │
│  │  - API 调用                      │  │
│  │  - SSE 流式接收                  │  │
│  │  - 会话本地缓存                   │  │
│  └──────────┬──────────────────────┘  │
│             │                          │
└─────────────┼─────────────────────────┘
              │ HTTP (port 8084)
              ▼
┌─────────────────────────────────────┐
│  minibox 后端（Go / N1 盒子）          │
│  - Agent 编排                        │
│  - LLM 调用                         │
│  - 终端执行                         │
│  - 记忆管理                         │
│  - MCP 工具                         │
└─────────────────────────────────────┘
```

**核心变化：** APP 不再内嵌 proot/Alpine 终端环境，所有文件操作、终端命令、Agent 编排都通过 HTTP API 转发给后端 minibox 服务。APP 体积从 ~100MB 降至 ~20MB（去除 .so 库和 Alpine rootfs）。

### 2.2 核心数据流设计

```
用户输入 "帮我查看 N1 的 CPU 温度"
      │
      ▼
┌─────────────────┐
│ ChatInputArea    │  用户输入并发送
│ (Compose)       │
└────────┬────────┘
         │ POST /api/chat/conversations/{id}/messages
         ▼
┌─────────────────┐
│ OkHttpClient    │  发送 HTTP 请求
│ (Retrofit)      │
└────────┬────────┘
         │ 后端处理...返回 SSE 流
         ▼
┌──────────────────────────────────────────┐
│ SSE EventSource (OkHttp RealWebSocket)    │
│                                          │
│ event: agent                            │
│ data: {"type":"start","tools":["ssh"]}   │
│                                          │
│ event: agent  data: {"type":"thinking"}  │──▶ DeepThinkingCard (动画)
│                                          │
│ event: agent  data: {"type":"tool_call"}  │──▶ ToolCallCard (加载态)
│                                          │
│ event: agent  data: {"type":"content"}    │──▶ StreamingText (逐字渲染)
│   data: {"delta":"N1 的 CPU 温度是..."}    │
│                                          │
│ event: agent  data: {"type":"tool_result"}│──▶ ToolResultCard (展示结果)
│                                          │
│ event: agent  data: {"type":"stop"}       │──▶ TypingIndicator 停止
│                                          │
│ event: done                              │──▶ 流结束
└──────────────────────────────────────────┘
         │
         ▼
┌─────────────────┐
│ MessageBubble    │  最终渲染为消息气泡
│ (Markdown)      │
└─────────────────┘
```

## 三、UI 突破方向 — 2025-2026 趋势调研

### 3.1 Material 3 Expressive（Google 2025 年 5 月发布）

minibox 2.0 应基于 **Kotlin + Jetpack Compose**（而非 Flutter），直接使用 Material 3 Expressive：

| 特性 | 说明 | minibox 应用场景 |
|---|---|---|
| `MaterialExpressiveTheme` | 全新主题包装器，内置弹性运动 | APP 根主题 |
| `MotionScheme.expressive()` | 全局弹性运动方案，替代线性动画 | 所有页面切换/组件交互 |
| `HorizontalFloatingToolbar` | 浮动工具栏组件 | 聊天输入框上方的快捷操作栏 |
| `SplitButtonLayout` | 分裂按钮（主操作+次操作） | 发送按钮 + 附件/语音按钮 |
| `LoadingIndicator` | 多边形变形加载器（Cookie9Sided 等） | Agent 思考中状态 |
| `ContainedLoadingIndicator` | 容器化加载指示 | 工具调用卡片加载态 |
| `defaultSpatialSpec()` | 空间弹性规范（缩放/平移/旋转） | 卡片展开/折叠微交互 |
| 形状变形 ~300ms | 圆角动态变化配合布局动画 | 消息气泡展开/工具卡片变形 |
| 15 个新/更新组件 | 更圆润/更粗字体/更严格触控目标 | 全 APP 组件 |

**Compose 最佳实践（来自 Google AI 概览）：**
- SSE token 批量缓冲：ViewModel 中用 `StateFlow` 缓冲，节流到 10-20 次/秒
- 隔离 Composable 范围：每条流式消息独立组件，避免 LazyColumn 全量重组
- `collectAsStateWithLifecycle()`：后台时安全暂停数据管道
- 触控目标 ≥ 48dp

## 四、技术选型建议

| 维度 | 推荐 | 理由 |
|---|---|---|
| 语言 | Kotlin | 与小万 Kotlin 部分一致，生态最好 |
| UI 框架 | Jetpack Compose | Material 3 Expressive 原生支持，Google 推荐 |
| 设计系统 | Material 3 Expressive | 15 个新组件 + 弹性运动 + 形状变形 |
| HTTP | Retrofit + OkHttp | 成熟稳定，支持 SSE/WebSocket 拦截 |
| SSE | OkHttp EventSource | 原生 SSE 流接收 |
| 本地存储 | Room (SQLite) | 会话缓存/离线消息 |
| 依赖注入 | Hilt | Google 推荐 DI |
| 导航 | Navigation Compose | Google 官方 |
| 图标 | Material Symbols Rounded | 最新图标系统 |
