## 一、完全解耦：前端与其他组件彻底分离

### 1.1 小万当前耦合现状（全量包结构）

小万 OmniBot 是一个"All-in-One"单体应用，前端（Flutter UI）与后端能力（Agent 引擎、LLM、终端、数据库）深度耦合在同一 APK 中：

```
┌──────────────────────────────────────────────────────────────┐
│                    OmniBot APK（单体）                        │
│                                                              │
│  ┌──────────┐   MethodChannel   ┌─────────────────────────┐  │
│  │ ui/      │◄────────────────►│ app/ (Kotlin Host)       │  │
│  │ Flutter  │   JSON 消息       │  ├─ agent/ 85kt 编排引擎 │  │
│  │ 407 dart │                   │  ├─ tool/ 27kt 工具系统  │  │
│  └──────────┘                   │  ├─ terminal 7kt ⚠proot │  │
│                                 │  ├─ termux 1kt ⚠        │  │
│  ┌──────────┐                   │  ├─ operit/terminal 7kt │  │
│  │ uikit/   │◄────────────────►│  ├─ mcp/ 14kt           │  │
│  │ 悬浮球/  │                   │  ├─ webchat/ 8kt        │  │
│  │ 宠物猫   │                   │  └─ ui/channel/ 20kt    │  │
│  └──────────┘                   └─────────┬───────────────┘  │
│                                           │                  │
│  ┌────────────────────────────────────────▼───────────────┐  │
│  │ baselib/（约 80 kt）共享基础库                            │  │
│  │  数据库(Room) / HTTP(OkHttp) / LLM供应商(10+) / Shizuku  │  │
│  │  / MMKV / 工具类                                          │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐   │
│  │ ReTerminal/（约 100 kt）proot 终端模拟器 + Alpine rootfs │   │
│  └────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

| `app/webchat/` | 8 kt | Web 聊天后端 | ❌ **移除** → 后端 | 后端已含 WebUI |

| `app/workspace/` | 2 kt | 工作区 | ❌ **移除** → 后端 | 后端 workspace |
| `baselib/` 基础库 | 80 kt | 数据库/HTTP/LLM/Shizuku | ⚠️ **部分保留** | 保留 Room+HTTP+工具类；移除 LLM 供应商/Shizuku |
| `assists/` | 18 kt | 任务执行系统 | ❌ **移除** → 后端 | 后端 Agent 已覆盖 |

| `ReTerminal/` | 100 kt | proot 终端 | ❌ **移除** | 完全删除（~30MB 体积） |

### 1.3 解耦后的纯前端架构（目标态）

```
┌─────────────────────────────────────────────────────────────┐
│              minibox-android 2.0（纯前端 ~20MB）             │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ Presentation 层（Jetpack Compose + M3 Expressive）     │  │
│  │  ├─ ui/chat/          聊天界面（流式/工具卡/思考动画）   │  │
│  │  ├─ ui/conversation/  会话抽屉/历史/搜索               │  │
│  │  ├─ ui/settings/      设置（含后端服务设置组）           │  │
│  │  ├─ ui/memory/        记忆中心/详情/标签               │  │
│  │  ├─ ui/agent/         Agent 管理/灵魂/画像            │  │
│  │  ├─ ui/tools/         工具管理/注册                   │  │
│  │  ├─ ui/logs/          日志/导出                       │  │
│  │  └─ ui/onboarding/    引导（后端连接配置）              │  │
│  └──────────┬────────────────────────────────────────────┘  │
│             │ ViewModel + StateFlow（节流 10-20fps）         │
│  ┌──────────▼────────────────────────────────────────────┐  │
│  │ Domain 层（UseCase / Mapper）                          │  │
│  └──────────┬────────────────────────────────────────────┘  │
│             │                                               │
│  ┌──────────▼────────────────────────────────────────────┐  │
│  │ Data 层                                                 │  │
│  │  ├─ api/       Retrofit 接口（64+2 端点）               │  │
│  │  ├─ sse/       OkHttp SSE 客户端（agent 事件流）        │  │
│  │  ├─ model/     DTO（与后端 JSON 严格对齐）               │  │
│  │  ├─ repository/ 仓库（网络+本地缓存双源）                 │  │
│  │  └─ db/        Room（会话列表/消息/设置缓存）             │  │
│  └─────────────────────────────────────────────────────────┘  │
│                                                             │
│  本地能力（仅保留与后端无关的）：主题/语言/触觉/悬浮球          │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP :8084 + SSE + MCP :8085
                           ▼
              ┌─────────────────────────────┐
              │   minibox 后端（Go/N1）      │
              │   Agent引擎/LLM/记忆/工具/   │
              │   终端/SSH/工作区/升级/日志   │
              └─────────────────────────────┘
```

**解耦的 5 个关键决策：**

1. **UI 框架切换**：Flutter → Jetpack Compose。理由：Material 3 Expressive 原生支持、后端契约是 JSON/SSE 与语言无关、小万 Dart 代码不能直接复用（但设计可参考）
2. **智能放后端**：Agent 编排、LLM 调用、工具执行、记忆存取、终端命令全部交给后端。前端零 AI 依赖
3. **本地仅缓存**：Room 只存会话索引、消息快照、设置项，用于离线展示和快速启动；数据权威在后端
4. **设置项动态化**：后端通过 config API 暴露配置结构，前端设置页根据返回的 schema 动态渲染（见第三部分）
5. **悬浮球保留**：作为独立模块，通过本地 HTTP 与聊天页通信，不依赖后端

## 二、基于互联网资料的架构优化

### 2.1 技术栈选型（2025-2026 最新）

| 维度 | 选型 | 依据（互联网调研） |
|---|---|---|
| UI 框架 | Jetpack Compose + Material 3 Expressive | Google 2025.5 发布，弹性运动/形状变形/15 新组件 |
| 导航 | Navigation Compose 2.9+（Type-safe routes） | 类型安全路由，避免字符串地狱 |
| 网络 | Retrofit 3 + OkHttp 5 + kotlinx.serialization | SSE 流式 + 拦截器 + 协程原生 |
| SSE | OkHttp EventSource + kotlinx.coroutines Flow | 后端 agent 事件流逐条消费 |
| 本地存储 | Room 2.7 + DataStore 1.1 | 会话缓存 + 设置持久化 |
| DI | Hilt 2.55 | 官方推荐 |
| 动画 | MotionScheme.expressive() + spring | 弹性物理运动 |
| 图标 | Material Symbols Rounded | 四轴可变（fill/wght/grad/size） |
| 模块化 | 单模块 + 包分层（先 Start Flat） | 生产建议：先扁平，避免过度模块化 |

### 2.2 聊天界面优化（核心）

**优化前（v1 教训）**：整屏刷新、无流式缓冲、工具调用隐藏、思考过程不可见

**优化后（基于 AI 聊天 UI 趋势）**：

| 特性 | 实现 | 来源 |
|---|---|---|
| 流式文本 | 逐字符 30ms 淡入 + 3px 上移；StateFlow 节流 10-20fps | Compose 最佳实践 |
| 思考可视化 | DeepThinking 卡片（脉冲点 600ms 周期）+ 可折叠 | 小万 deep_thinking_card 设计 |
| 工具调用 | 卡片流：Shimmer 骨架 → 执行中脉冲 → 结果展开（SharedTransition） | 小万 card_widget_factory 设计 |
| 打字指示器 | 顺序脉冲点 + "思考中…"标签 | Ambient Typing Indicator 趋势 |
| 停止按钮 | Send 按钮 SplitButtonLayout 变形为 Stop | M3 Expressive 新组件 |
| 消息气泡 | 形状变形 ~300ms（12dp→24dp 圆角）+ spring 弹性 | M3 形状变形 |
| 错误状态 | 红色左边框 + 抖动 spring + 重试按钮 | Transparent AI 趋势 |
| 空状态 | 渐变背景 + 浮动 Logo + typewriter 欢迎语 | Bento Grid 趋势 |
| 底部锚条 | 新消息到达自动滚动 + 锚条淡入 | 聊天 UX 最佳实践 |

### 2.3 全局交互优化（2026 趋势落地）

| 趋势 | 落地方式 |
|---|---|
| **Generative UI** | 后端 config API 返回结构化配置 → 前端动态渲染设置表单 |
| **Confidence Indicators** | 工具结果卡片显示成功/失败/不确定三态色带 |
| **Liquid Glass** | 悬浮球/底部工具条/模态用毛玻璃（严格限定临时层） |
| **Bento Grid** | 记忆中心/我的页/工具页用便当盒网格布局 |
| **Dark as Default** | 默认深色主题 + 动态取色（Dynamic Color） |
| **手势导航** | 左滑返回/右滑抽屉/长按消息快捷操作 + 触觉反馈 |
| **Transparent AI** | 每轮回复展示：思考→工具→结果→总结 全流程时间线 |
| **Proactive UI** | 启动时预连接后端/预取会话列表/预加载模型列表 |

## 四、补充建议

### 4.1 开发节奏建议

| 阶段 | 范围 | 说明 |
|---|---|---|
| **P0 骨架** | 工程搭建 + 数据层（Retrofit/SSE/Room）+ 聊天界面 + 会话列表 + 服务器连接设置 | 最小可用，先连上后端 |
| **P1 功能** | Agent/模型/记忆/工具管理页 + 灵魂/画像 + 引导流程 | 覆盖 64 API 的 80% |
| **P2 体验** | 升级中心 + 日志中心 + 配置管理 + 悬浮球 + 全部动画打磨 | 全功能 + 精致 |
| **P3 增值** | 宠物猫移植 + 语音 + 国际化 + 深色细节 | 差异化 |

### 4.2 架构原则（防坑清单）

1. **DTO 与后端 JSON 严格对齐**：用 kotlinx.serialization 的 `@SerialName` 显式映射中文字段
2. **SSE 断线重连**：指数退避 + 心跳超时检测；重连后拉取消息增量
3. **配置动态渲染**：不要硬编码设置表单，用后端 config 的 schema 驱动
4. **本地缓存降级**：后端离线时，聊天页显示缓存会话，禁止白屏
5. **API Key 不入前端**：所有密钥只存后端（供应商配置在后端），前端零密钥
6. **超时策略**：SSE 读超时 120s；普通 API 读 30s；健康检查 5s
7. **体积控制**：去除 ReTerminal/rootfs 后 ~20MB；悬浮球和宠物用独立 module 按需打包
8. **测试**：先用 `POST /tools/{name}/invoke` 和 `POST /agents/{name}/stream` 做冒烟测试，再写 UI

### 4.3 可复用的设计资产（从小万提取）

即使改用 Compose，以下设计值得参考移植：
- **Card 工厂模式**：统一消息卡片分发（工具/产物/思考/错误）
- **chat_page 拆分法**：按职责拆分大页面（lifecycle/model/ui/flow）
- **命令覆盖层**：气泡+输入框+卡片作为独立子系统
- **深度思考三件套**：parser + persistence + card
- **宠物猫（uikit）**：DraggableBall + SpriteAtlas 精灵动画，可直接移植
