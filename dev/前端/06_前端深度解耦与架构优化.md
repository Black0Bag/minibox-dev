# minibox 2.0 前端深度解耦与架构优化方案

> 基于小万 OmniBot 全量源码包结构分析（407 Dart + 414 Kotlin + 64 services + 6 模块）
> + minibox 后端 66 API + SSE 协议 + 2025-2026 UI 趋势
> 日期：2026-08-01

---

## 一、完整解耦：小万前端 vs 后端组件

### 1.1 小万 6 大模块解耦分类

小万 OmniBot 有 6 个顶层模块，按"是否可搬到 minibox 纯前端"分为三类：

```
OmniBot/
├── ✅ 可直接搬迁（纯 UI / 纯前端逻辑）
│   ├── ui/                    Flutter UI 主体（407 Dart）
│   ├── webchat/               React WebUI（19 tsx/ts）
│   ├── uikit/                 悬浮球/半屏面板（10 kt）
│   └── baselib/               基础库（~70 kt）
│
├── 🔧 需要改造后搬迁（替换数据源为后端 API）
│   ├── app/agent/             Agent 引擎 → 删除，由后端 minibox 接管
│   ├── app/mcp/               MCP 服务 → 删除，由后端 :8085 接管
│   ├── app/ui/channel/        Flutter Platform Channel → 改为 HTTP 客户端
│   ├── app/voice/             语音服务 → 保留本地 + 后端 API
│   ├── app/webchat/           本地 WebChat 服务器 → 删除，直接用后端
│   ├── assists/               辅助功能 → 简化为本地任务管理
│   └── baselib/llm/           LLM Provider → 删除全部，后端统一管
│
└── ❌ 完全移除（proot/终端依赖）
    ├── ReTerminal/            嵌入式终端 + proot 运行时（~100 文件）
    ├── app/terminal/          终端生命周期管理（7 kt）
    ├── app/termux/            Termux 命令执行（1 kt）
    ├── com/ai/.../operit/     Operit 遗留终端（7 kt + 5 子目录）
    └── baselib/shizuku/       Shizuku 高权限 shell（6 kt）
```
