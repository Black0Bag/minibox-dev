# Android 前端解耦与架构基准

## 解耦结论

minibox-android 是纯 Kotlin/Compose 客户端，不复用旧 Flutter/proot/终端/LLM Provider/Agent Runtime。旧应用只能提供交互和设备能力参考，不能直接搬运架构。

## 目标分层

```text
UI / Navigation
    ↓ events        ↑ immutable state
ViewModel / feature reducer
    ↓
Repository
    ↓
REST client | SSE client | WebSocket device client
    ↓
minibox Go backend
```

- `core:model`：统一 Envelope、Problem、JSON-RPC 和业务 DTO。
- `core:network`：REST/SSE/WS、重连、超时、脱敏日志。
- `data`：Repository 和可替换缓存。
- `feature:*`：chat、knowledge、device、settings、monitor、schedule、teamwork。
- `designsystem`：主题、图标、通用状态组件和无障碍基线。

## 状态管理

- ViewModel 暴露单一不可变 `UiState`；用户操作以事件函数上行。
- Screen 使用 `collectAsStateWithLifecycle()`。
- Composable 不直接调用网络、不保存 Repository、不在组合体内启动无界任务。
- SSE/WS reducer 应是可单测的纯状态转换。

## Navigation 3

- 路由实现可序列化 `NavKey`。
- 使用 `rememberNavBackStack` 保存配置变更后的 back stack。
- `NavDisplay` 通过 entry provider 映射路由到无状态内容。
- 顶层会话/知识/设备/管理可保留独立 back stack。
- 路由只传 ID 和少量值，详情数据由 ViewModel/Repository 加载。

## 网络边界

- REST：短请求和状态变更；统一解析 Envelope/Problem。
- SSE：Agent/系统事件；一个 session 一个流，按 seq 去重和回放。
- WS：设备双向 RPC；一个读循环、pending map、心跳和重连。
- 不用全局 EventBus 隐藏业务流；连接状态作为显式 StateFlow。

## 设备能力边界

设备执行器与 UI/网络隔离：网络只产生受控命令 DTO，执行器验证能力、Android 权限和审批状态后才操作系统。结果通过同一 JSON-RPC ID 回传。

## 本地存储

- DataStore：服务器地址、主题、非敏感偏好。
- Keystore/加密存储：设备 token。
- Room：仅在明确需要离线索引/草稿时引入；不能成为后端数据副本或冲突源。

## 明确不引入

- 本地 LLM Provider/AgentLoop/MCP 服务端。
- proot/Termux 运行时。
- 直接 SQLite/SFTP 业务数据访问。
- 尚无后端契约的占位功能按钮。

## 测试边界

- reducer/ViewModel 单测；Repository 使用 fake clients。
- MockWebServer 测 REST/SSE；本地 WS fixture 测乱序响应。
- Compose UI 测语义、错误状态和主流程。
- 真机无障碍/MediaProjection/Shizuku 分能力授权验收，不放进普通 CI。
