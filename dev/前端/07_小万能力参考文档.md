## 二、小万前端能力清单（与 minibox 后端交叉互动视角）

### 2.1 ✅ 手机屏幕操控（VLM 视觉语言模型）

**小万工具**：`vlm_task`

| 能力 | 说明 | minibox 对标 |
|------|------|-------------|
| 屏幕截图 | 通过 MediaProjection 截取屏幕 | minibox 前端有 BrowserProxyService（WebView），但无全局截屏 |
| 视觉理解 | VLM 模型分析截图内容 | minibox 无此能力 |
| 自动操作 | 点击/输入/滑动/长按/返回/Home | minibox 前端有 DeviceExecutor（7 项能力），但缺 VLM 决策层 |
| 任务阻塞 | 阻塞等待直到任务完成/用户输入/超时 | minibox SSE 是单向推送，无阻塞式任务模型 |
| 风控检测 | 检测到验证码/风控时停止并请用户接管 | minibox 无此机制 |

**借鉴价值**：🔴 高。minibox 的 DeviceExecutor 有底层操控能力，但缺少 VLM 视觉决策层。可以在 minibox 后端 Agent 工具系统中注册一个 `device_screen_task` 工具，通过 WebSocket 下发截图+操作指令到前端执行。

### 2.2 ✅ 浏览器自动化

**小万工具**：`browser_use`

| 能力 | 说明 | minibox 对标 |
|------|------|-------------|
| 离屏浏览器 | 最多 3 个标签页 | minibox 有 BrowserProxyService（WebView + JS 注入） |
| 页面导航 | navigate + screenshot + click + type | minibox 前端有 WebView loadUrl + injectScript |
| 内容提取 | get_text + get_readable + get_backbone | minibox 无结构化内容提取 |
| 无限列表 | scroll_and_collect | minibox 无此能力 |
| Cookie 管理 | get_cookies + offload env | minibox 无 Cookie 管理 |
| 风控检测 | riskChallengeDetected + 自动停止 | minibox 无风控机制 |
| JS 执行 | execute_js | minibox 有 injectScript 但未实现 |
| 桌面/移动 UA 切换 | set_user_agent | minibox 无 |

**借鉴价值**：🔴 高。小万的 browser_use 是完整的离屏浏览器工具链（7 个 Kotlin 文件 + Flutter UI）。minibox 的 BrowserProxyService 目前只有 WebView 基础壳，可以借鉴小万的 action 枚举设计（navigate/screenshot/click/type/get_text/scroll/find_elements/hover/get_readable/set_user_agent/get_backbone/execute_js/fetch/new_tab/close_tab/list_tabs/get_cookies/scroll_and_collect/go_back/go_forward/press_key/wait_for_selector）。

### 2.3 ✅ 终端环境（Alpine proot）

**小万工具**：`terminal_execute` + `terminal_session_*`

| 能力 | 说明 | minibox 对标 |
|------|------|-------------|
| Alpine Linux proot | 完整的 Linux 环境（非 chroot） | minibox 无终端环境 |
| 一次性命令 | `terminal_execute` 非交互单次命令 | — |
| 会话保持 | `terminal_session_start/exec/read/stop` 多轮保留 cwd/环境 | — |
| Python/uv | 自动 .venv 管理 + uv 包管理器 | — |
| 工具自动补齐 | 缺失 CLI 工具自动安装 | — |

**借鉴价值**：🟡 中。这是小万的"杀手锏"能力。minibox 作为路由器上的 Go 后端，本身不需要终端环境，但如果 minibox 前端（Android APP）能内嵌一个类似的 proot 终端，就能让 minibox Agent 也具备本地代码执行能力。实现成本较高，建议放在远期规划。

## 五、总结

小万 APP 是一个功能完整的 AI Agent 客户端，其前端能力远超 minibox 当前前端。核心差异在于：

1. **VLM 视觉操控**：小万有完整的截屏→视觉理解→自动操作链路，minibox 前端有底层操控能力但缺 VLM 决策层
2. **离屏浏览器**：小万有 21 种浏览器操作，minibox 前端只有 WebView 壳
3. **终端环境**：小万有完整 Alpine Linux proot 环境，minibox 无
4. **记忆系统**：两者架构一致，但小万有完整的前端管理 UI，minibox 只有后端引擎
5. **Skills 系统**：小万有结构化的 skill 组织（SKILL.md + scripts + references），minibox 用 MCP 工具但组织松散

**推荐行动**：优先将 VLM 屏幕操控和浏览器自动化能力通过 WebSocket 协议接入 minibox 后端 Agent 工具系统（阶段 2），让 minibox Agent 也能获得"眼耳口手"能力。
