# 旧 APP 能力参考（精简）

> 本文只列可借鉴能力，不代表 minibox 已实现，也不作为技术架构来源。

## 高价值参考

| 能力 | 可借鉴点 | minibox 当前边界 |
|---|---|---|
| 屏幕操控 | MediaProjection、Accessibility 手势、失败后再截图验证 | 后端有设备工具和模拟协议；Android 执行器未开发 |
| 浏览器代理 | WebView 导航、截图、DOM 文本、验证码人工接管 | 后端仅有 WS browser 方法族占位 |
| 设备前台服务 | 长连接、心跳、ROM 保活引导 | Android 工程未建立 |
| 风控接管 | 遇验证码/敏感动作停止并请求用户 | 后端危险设备动作 fail-closed；审批提交 API 待补 |
| 通知与语音 | NotificationListener、TTS、SpeechRecognizer | 设备工具已定义；真机能力未验收 |
| 文件能力 | 受控读写、路径边界、审计 | 后端有文件工具；手机端执行边界待设计 |

## 不采用

- Flutter + Kotlin 混合 UI。
- Alpine proot/Termux 作为应用核心。
- 前端自行运行 Agent、LLM Provider 或 MCP 服务端。
- 将后端数据复制成前端第二事实源。

## 借鉴原则

1. 只复用已经证明有用户价值的交互模式。
2. 每项能力重新按 Android 当前 API、权限和隐私规则实现。
3. 能力必须先有后端契约和安全状态，再做 UI。
4. 真机副作用逐项授权，不因参考应用存在就默认可用。
