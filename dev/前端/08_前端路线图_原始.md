## 0. 文档定位与切割原则

- 总路线图 Phase 0-6 是前后端混合路线图，本文件将其按职责切割为**纯前端路线图**。
- 切割原则：前端负责「眼耳口手」——所有 UI 渲染、设备控制层、浏览器代理、通知展示、用户交互。
- 后端负责的逻辑、数据存储、API 服务等不在本文件范围。
- 前后端**协同项**（需双方同步开发的接口/协议）在本文件中以「🔗协同」标注。

## 2. Phase 依赖关系

```
Phase F0 (协议地基)
  ├→ Phase F1 (聊天内核)
  ├→ Phase F2 (知识库前端) ← 需后端 Phase 1 完成
  ├→ Phase F3 (设备控制层) ← 需后端 Phase 3 完成
  ├→ Phase F4 (通知与在线)  ← 需后端 Phase 4 完成
  ├→ Phase F5 (备份+设置)   ← 需后端 Phase 5 完成
  └→ Phase F6 (扩展体验)    ← 需 F1-F5 基础
       └→ Phase F7 (PC端占位)
```

- F0 是所有前端模块的基础（协议层）
- F1 可在 F0 完成后独立启动（聊天是最先需要的体验）
- F2-F5 各需后端对应 Phase 完成才能联调
- F6 是扩展层，非 MVP 必需
- F7 可最早做占位设计，实际开发排后
