# minibox-agent 开发备忘录

> 本文件是 minibox-agent 项目的原始需求记录，防止上下文记忆丢失。
> 创建时间：2026-07-31
> 所有后续开发工作必须以本文件为最高需求基准。

---

## 一、总纲

- 使用 Go 语言编写
- 全面对简体中文进行强优化，只要是非机器语言尽可能全部使用简体中文
- 代码注释、配置文件、CLI 输出、API 文档、错误信息等一律使用简体中文
- 机器语言（Go 关键字、标准库函数名、SDK API 名）保持英文

## 二、多供应商 LLM API 接入

- 具备多供应商接入云 LLM API 的能力
- API 支持多 Key 轮询
- 检测到当前 Key 所使用的模型受限或出现问题时，及时切换到下一个 Key
- LLM 层需支持思考强度（Thinking/Reasoning Effort）参数传递，覆盖以下供应商的思考模式：
  - DeepSeek：`reasoning_effort` 参数
  - OpenAI（o 系列）：`reasoning_effort` 参数（low/medium/high）
  - Anthropic：`thinking` 参数（extended thinking，budget_tokens）
  - 通用降级：如果供应商不支持思考强度参数，自动忽略不报错
- 思考强度统一抽象为 5 档：`关闭` / `低` / `中` / `高` / `最高`，由 LLM 层适配各供应商的具体参数格式
- 供应商类型包括但不限于：OpenAI 兼容接口、Anthropic、Gemini 等

## 三、记忆系统（代码级集成 sage-wiki 内核）

- 具备记忆系统，涉及：
  - 短期记忆
  - 长期永久记忆
  - 其他用户添加的记忆
  - 灵魂文件（SoUL）
  - 用户画像等记忆
- **本记忆系统使用 sage-wiki 项目内核逻辑核心，代码级集成，非兼容性集成**
- 不保留 sage-wiki 的包结构、类型名、函数签名
- 将 sage-wiki 的核心算法逻辑拆散重写进 minibox 自己的包结构里
- 最终代码库中搜不到 "sage-wiki" 这个词，搜不到 sage-wiki 原始类型名

### 保留的 sage-wiki 核心算法

1. **SQLite WAL 连接管理**：读写分离、WAL 模式、busy_timeout、schema 版本迁移
2. **FTS5 全文索引**：中文分词优化、BM25 搜索、停用词过滤、FTS5 特殊字符防注入
3. **向量余弦相似度**：float32 ↔ bytes 编码、top-k 有序切片维护、全表扫描
4. **RRF 融合搜索**：BM25 + 向量结果融合、时间衰减加权、标签加权
5. **Embedding API 调用**：OpenAI/Ollama embedding、限速器、多 Provider 级联

## 四、MCP 知识库输出功能

- 从 sage-wiki 引入的知识库记忆系统保留 MCP 知识库输出功能
- 供其他 Agent 智能体通过 MCP 协议调用本 Agent 的知识库
- sage-wiki 原有的 MCP 工具不应该被盲目删减
- 需要保留的 MCP 工具（基于 sage-wiki `internal/mcp/`）：
  - 知识库搜索（hybrid search）
  - 知识库写入（add entry）
  - 知识库读取（get entry）
  - 知识库更新（update entry）
  - 知识库删除（delete entry）
  - 记忆检索
  - 记忆写入
  - 以及其他与知识库/记忆相关的 MCP 工具
- MCP 工具需适配 minibox 的中文命名和接口风格

## 五、工具系统（接口模式）

- Agent 具备的工具：SubAgent 子代理、To-Do List、Skill、插件等
- 工具系统使用接口模式设计
- 后期发现好的模式工具可以方便集成进 Agent 供 LLM 模型调用
- 工具注册采用统一接口，支持运行时动态注册

## 六、环境检测与初始化

- 编译的二进制被运行前检测环境状态：
  - 是否有配置文件
  - 是否有记忆系统数据库
- 如果有 → 按照用户命令直接运行
- 如果没有 → 提示错误，要求按步骤先使用配置模式启动二进制

### 配置模式

- 生成配置文件
- 生成记忆系统数据库
- 释放一个文件夹，内部包括：

#### 自升级脚本
- Agent 从 GitHub 下载最新二进制文件后执行此脚本
- 脚本流程：
  1. 关闭 Agent 进程
  2. 备份原二进制
  3. 把新的二进制移动到正确位置并赋予权限
  4. 按设定命令重启
  5. 记录脚本执行期间的日志
  6. 如果一段时间检测到二进制没有正确运行，立刻回退到备份的二进制

#### 运行时安装脚本
- 安装 Git、Python 等工具
- 检测当前系统架构
- 直接下载对应二进制并赋予权限
- 写入 Agent 的自带配置文件（不写入系统级环境变量）

## 七、CLI 功能定位

- Agent 具备简单的 CLI 配置基础功能
- **不应提供对话等高级功能**
- 高级功能全部使用 API 被单独的前端控制
- CLI 功能包括：
  - 配置模式（初始化配置文件和数据库）
  - 启动服务模式（启动 HTTP API 服务器）
  - 版本信息
  - 自升级触发
  - 基本状态检查

## 八、API 接口

- 提供全方位多 API 供前端控制 Agent 的行动逻辑
- **核心原则：尽可能把所有功能全部以 API 形式被前端进行调用，不设暗箱**
- API 覆盖范围：
  - 对话 / 消息发送 / 消息流式传输（SSE）
  - 对话参数控制：思考强度、温度、Top-P、最大 Token、频率惩罚、存在惩罚等模型参数全部通过 API 可调
  - 思考强度：支持设置模型的推理深度（如 DeepSeek 的 reasoning effort、OpenAI 的 reasoning effort、Anthropic 的 extended thinking 等），前段可通过 API 控制开关和强度级别
  - Agent 配置管理（创建/修改/切换 Agent）
  - 记忆管理（增删改查各类记忆、按类型筛选、批量操作）
  - 工具管理（注册/查询/调用工具、动态加载/卸载插件）
  - 知识库管理（MCP 工具对外暴露、搜索/写入/读取/删除/编译）
  - 会话管理（创建/列举/删除/切换会话、会话历史检索）
  - LLM 供应商管理（增删改查供应商、Key 轮询状态查看、手动切换供应商/Key、供应商健康检查）
  - 模型参数管理（针对每个供应商可设默认参数，对话时可覆盖参数）
  - 系统状态/健康检查（运行状态、数据库状态、记忆统计、供应商状态）
  - 升级管理（检查更新/触发升级/查看升级日志/回滚）
  - 运行时工具管理（Git/Python 等工具的安装状态查询、手动安装触发）
- API 设计 RESTful 风格，支持 SSE 流式响应
- API 响应统一使用简体中文
- 所有配置项均通过 API 可读可改，不存在"只能改配置文件不能改 API"的暗箱功能
- 对话请求支持传递完整模型参数覆盖，包括但不限于：
  - `思考强度`：off / low / medium / high / max（对应各供应商的 thinking/reasoning 参数）
  - `温度`：0.0 ~ 2.0
  - `TopP`：0.0 ~ 1.0
  - `最大Token`：整数
  - `频率惩罚`：-2.0 ~ 2.0
  - `存在惩罚`：-2.0 ~ 2.0
  - `停止序列`：字符串数组
  - `自定义系统提示词`：字符串（覆盖 Agent 默认灵魂提示词）
  - `记忆注入控制`：是否注入记忆 / 注入哪些类型记忆 / 记忆条数上限

## 九、技术约束

- Go 版本：1.25+
- SQLite 驱动：modernc.org/sqlite（纯 Go，无 CGO）
- HTTP 路由：chi
- 配置格式：YAML
- 交叉编译目标：路由器 ARM aarch64（MT6000）、Linux x86_64、Windows
- 零 CGO 依赖
- 二进制应尽量精简

## 十、专用模型分配（功能级模型独立配置）

- **核心原则：所有调用 LLM 模型的功能全都可以单独设置专用模型，不强制共用一个模型**
- 每个功能可以独立绑定：指定供应商 + 指定模型 + 独立的模型参数（思考强度/温度/TopP等）
- 如果某功能未设置专用模型，则按优先级链回退到默认值

### 需要独立配置模型的功能清单

| 功能 | 配置键 | 说明 |
|---|---|---|
| 主 Agent 对话 | `主Agent对话` | 主 Agent 日常对话使用的模型 |
| 子 Agent 对话 | `子Agent对话` | SubAgent 子代理执行任务使用的模型（可用更低成本模型） |
| 记忆编译 | `记忆编译` | 记忆系统编译/压缩/总结使用的模型 |
| 记忆嵌入 | `记忆嵌入` | Embedding 向量化使用的模型（通常为专用 embedding 模型） |
| 灵魂文件生成 | `灵魂生成` | 自动生成/更新灵魂文件时使用的模型 |
| 用户画像分析 | `画像分析` | 分析用户行为、生成/更新用户画像时使用的模型 |
| 工具决策 | `工具决策` | Agent 决定调用哪个工具时使用的模型（可用快速低成本模型） |
| 知识编译 | `知识编译` | MCP 知识库编译功能使用的模型 |

### 模型分配配置结构

```yaml
模型分配:
  主Agent对话:
    供应商: "DeepSeek"
    模型: "deepseek-chat"
    参数:
      思考强度: "中"
      温度: 0.7
  子Agent对话:
    供应商: "DeepSeek"
    模型: "deepseek-chat"
    参数:
      思考强度: "低"
      温度: 0.5
  记忆编译:
    供应商: "DeepSeek"
    模型: "deepseek-chat"
    参数:
      思考强度: "中"
      温度: 0.3
  记忆嵌入:
    供应商: "OpenAI"
    模型: "text-embedding-3-small"
    维度: 1536
  灵魂生成:
    供应商: "DeepSeek"
    模型: "deepseek-chat"
    参数:
      思考强度: "高"

    供应商: "DeepSeek"
```

### 模型分配 API

| 方法 | 路径 | 功能 |
|---|---|---|
| `GET` | `/api/v1/模型分配` | 获取全部功能模型分配 |
| `GET` | `/api/v1/模型分配/{功能名}` | 获取指定功能的模型分配 |
| `PUT` | `/api/v1/模型分配/{功能名}` | 设置指定功能的专用模型 |
| `DELETE` | `/api/v1/模型分配/{功能名}` | 清除指定功能的专用模型（回退到默认） |

### 模型参数优先级链（最终确定值）

```
1. 对话请求中的 model参数字段     ← 最高优先级（逐次对话覆盖）
2. 模型分配[功能名].参数           ← 该功能的专用模型配置
3. 供应商[名称].默认模型参数       ← 供应商级默认参数
4. 系统全局默认                    ← 最低优先级（兜底）
```

### 对话请求中的模型覆盖扩展

```json
{
  "模型覆盖": {
    "供应商": "DeepSeek",
    "模型": "deepseek-reasoner",
    "思考强度": "高",
    "温度": 0.5
  }
}
```
> 当 `模型覆盖` 字段存在时，优先使用其中指定的供应商 + 模型 + 参数，忽略该功能的默认模型分配。

## 十、项目结构规划

```
minibox/
├── cmd/minibox/main.go          ← CLI 入口
├── internal/
│   ├── agent/                   ← Agent 定义、Dispatcher、SubAgent
│   ├── api/                     ← HTTP 路由、SSE、API 处理器
│   ├── config/                  ← 配置解析、初始化检测
│   ├── engine/                  ← AgentLoop、模式路由
│   ├── llm/                     ← 多供应商、多 Key 轮询、Embedding
│   ├── memory/                  ← 记忆系统（SQLite + FTS5 + 向量 + RRF）
│   ├── mcp/                     ← MCP 服务端、知识库工具暴露
│   ├── storage/                 ← SQLite WAL 存储层
│   ├── tools/                   ← 工具接口、注册、内置工具
│   └── upgrade/                 ← 自升级、安装脚本释放
├── go.mod
├── go.sum
└── Makefile                     ← 交叉编译
```
