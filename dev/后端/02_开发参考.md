## 一、Go Agent 框架借鉴

### 1.1 推荐借鉴：CloudWeGo Eino（12.6k star）

| 项目 | 值 |

**值得借鉴的 5 个设计模式**：

1. **AgentLoop + Iterator 模式**：Agent 执行返回事件迭代器，天然支持流式输出
```go
runner := adk.NewRunner(ctx, adk.RunnerConfig{Agent: agent})
iter := runner.Query(ctx, "你好")
for {
    event, ok := iter.Next()
    if !ok { break }
    fmt.Println(event.Message.Content)
}
```

2. **Callback Aspect 切面**：固定切点注入横切关注点（日志/追踪/指标），比传统回调更优雅
```go
// 固定切点：OnStart / OnEnd / OnError / OnStartWithStreamInput / OnEndWithStreamOutput
```

3. **Graph -> Tool 桥接**：确定性工作流可暴露为 Agent 可调用的工具

4. **DeepAgent 多代理协调**：任务分解 + 子代理委托 + 进度追踪
```go
deepAgent, _ := deep.New(ctx, &deep.Config{
    ChatModel: chatModel,
    SubAgents: []adk.Agent{researchAgent, codeAgent},
})
```

5. **企业级可靠性**：内置断路器、指数退避重试、超时、批量隔离

### 1.3 minibox Agent 架构建议

综合 Eino + LangChainGo 的最佳实践，minibox 的 Agent 层应采用：

```
AgentLoop（核心循环）
  ├── 最大迭代限制（MaxIterations）
  ├── 记忆钩子（每轮注入/写入记忆）
  ├── 工具决策（LLM 选择工具 -> 执行 -> 观察）
  ├── 流式事件输出（Iterator/Channel 模式）
  └── 错误恢复（重试/降级/切换供应商）
```

### 2.3 多供应商兼容方式（借鉴 go-openai）

go-openai 通过 **BaseURL 覆盖 + APIType 切换** 实现多供应商：


**认证 Header 差异**：
- OpenAI: `Authorization: Bearer sk-xxx`
- Anthropic: `x-api-key: sk-ant-xxx` + `anthropic-version: 2023-06-01`
- Gemini: URL 参数 `?key=xxx` 或 `x-goog-api-key` header

```go
// 余弦相似度计算
func 余弦相似度(a, b []float32) float64 {
    var 点积, 模a, 模b float64
    for i := range a {
        点积 += float64(a[i]) * float64(b[i])
        模a += float64(a[i]) * float64(a[i])
        模b += float64(b[i]) * float64(b[i])
    }
```

## 五、SSE 流式响应

### 5.1 Go 原生 SSE（不依赖第三方库）

```go
// SSE 协议核心：
// 1. Content-Type: text/event-stream
// 2. 写入后必须调用 Flush()，否则数据被缓冲
// 3. 事件格式：field: value\n，事件间用 \n\n 分隔

type SSE写入器 struct {
    w       http.ResponseWriter
    flusher http.Flusher
}

func 新建SSE写入器(w http.ResponseWriter) (*SSE写入器, error) {
    flusher, ok := w.(http.Flusher)
    if !ok { return nil, fmt.Errorf("不支持流式写入") }
    w.Header().Set("Content-Type", "text/event-stream")
    w.Header().Set("Cache-Control", "no-cache")
    w.Header().Set("Connection", "keep-alive")
    w.Header().Set("X-Accel-Buffering", "no")  // 禁用 Nginx 缓冲
    flusher.Flush()
    return &SSE写入器{w: w, flusher: flusher}, nil
}

func (s *SSE写入器) 写入事件(事件类型 string, 数据 string) error {
    if 事件类型 != "" {
        fmt.Fprintf(s.w, "event: %s\n", 事件类型)
    }
    fmt.Fprintf(s.w, "data: %s\n\n", 数据)
    s.flusher.Flush()
    return nil
}
```

### 6.3 统一响应格式

```go
type 统一响应 struct {
    成功 bool        `json:"成功"`
    数据 interface{} `json:"数据,omitempty"`
    错误 *错误信息   `json:"错误,omitempty"`
    元信息 元信息    `json:"元信息"`
}

type 错误信息 struct {
    代码 string `json:"代码"`
    消息 string `json:"消息"`
}

// 统一 JSON 响应中间件
func 响应JSON(w http.ResponseWriter, 状态码 int, 数据 interface{}) {
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(状态码)
    json.NewEncoder(w).Encode(统一响应{
        成功: 状态码 < 400,
        数据: 数据,
        元信息: 元信息{
            时间戳: time.Now().Format(time.RFC3339),
            请求ID: middleware.GetReqID(r.Context()),
        },
    })
}
```

```go
// 回滚
if err != nil {
    if rerr := selfupdate.RollbackError(err); rerr != nil {
        log.Printf("回滚失败: %v", rerr)
    }
}
```

**两阶段提交**：
1. `PrepareAndCheckBinary`：新二进制写入临时文件 + 校验
2. `CommitBinary`：旧二进制重命名为备份 + 新二进制移动到位

### 7.3 GitHub Release API 下载

```go
// 1. 查询最新版本
resp, _ := http.Get("https://api.github.com/repos/Black0Bag/minibox/releases/latest")
var release GitHubRelease
json.NewDecoder(resp.Body).Decode(&release)

// 2. 匹配架构
目标架构 := runtime.GOOS + "-" + runtime.GOARCH  // 如 linux-arm64
for _, asset := range release.Assets {
    if strings.Contains(asset.Name, 目标架构) {
        下载URL = asset.BrowserDownloadURL
        break
    }
}

// 3. 下载并应用
resp, _ := http.Get(下载URL)
err := selfupdate.Apply(resp.Body, selfupdate.Options{})
```

### 7.4 回滚脚本模式（shell）

minibox 备忘录要求释放一个自升级脚本，流程如下：

```bash
#!/bin/sh
# 自升级脚本 - 由 minibox 配置模式释放

AGENT_PID=$(pgrep -f "minibox")
BIN_PATH=$(which minibox)
BACKUP_DIR="backups"
TIMESTAMP=$(date +%Y%m%d%H%M%S)
LOG_FILE="upgrade-${TIMESTAMP}.log"

# 1. 关闭 Agent 进程
kill $AGENT_PID >> $LOG_FILE 2>&1

# 2. 备份原二进制
cp $BIN_PATH $BACKUP_DIR/minibox.${TIMESTAMP} >> $LOG_FILE 2>&1

# 3. 移动新二进制
mv /tmp/minibox-new $BIN_PATH >> $LOG_FILE 2>&1
chmod +x $BIN_PATH >> $LOG_FILE 2>&1

# 4. 重启
nohup $BIN_PATH 启动 >> $LOG_FILE 2>&1 &

# 5. 健康检查（30s 超时）
sleep 5
for i in $(seq 1 6); do
    if curl -s http://localhost:8084/api/v1/状态 > /dev/null 2>&1; then
        echo "升级成功" >> $LOG_FILE
        exit 0
    fi
    sleep 5
done

# 6. 回退
echo "健康检查失败，回退..." >> $LOG_FILE
cp $BACKUP_DIR/minibox.${TIMESTAMP} $BIN_PATH >> $LOG_FILE 2>&1
chmod +x $BIN_PATH >> $LOG_FILE 2>&1
nohup $BIN_PATH 启动 >> $LOG_FILE 2>&1 &
echo "已回退到备份版本" >> $LOG_FILE
```

### 7.5 跨平台注意事项

- **Windows**：无法替换正在运行的可执行文件，需要先重命名旧文件再写入新文件
- **Linux/Mac**：可以直接替换正在运行的可执行文件（inode 不变）
- **ARM 交叉编译**：`GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build`
- **架构检测**：`runtime.GOOS` + `runtime.GOARCH` 确定下载哪个二进制

## 十、跨语言 Agent 框架借鉴（Python/TS 生态）

> 互联网上最成熟的 Agent 方案大量在 Python/TS 生态，虽然不能借代码，但核心运行逻辑值得学习。
> 详细报告：ai-agent-frameworks-research.md / ai-agent-memory-systems-research.md

### 10.1 LangChain / LangGraph (Python, 143k star)

**三代架构演进**：
1. AgentExecutor（经典 ReAct 循环）
2. LCEL（声明式管道：`prompt | model | parser`，统一 Runnable 协议）
3. LangGraph（有向有环图：State + Node + Edge + Reducer）

**5 个值得借鉴的模式**：
1. **Runnable 统一协议**：所有组件实现 invoke/stream/batch 统一接口 → minibox 定义 `Invocable` 协议
2. **State + Reducer**：状态在循环各步骤间传递与合并
3. **Pydantic 驱动工具 Schema**：结构体定义自动生成工具描述和参数校验（Go 用 struct tag + 反射）
4. **Checkpointer 持久化**：检查点实现 Agent 状态持久化和恢复，支持中断续做
5. **Callback 全生命周期钩子**：on_llm_start / on_tool_start / on_tool_end / on_agent_action / on_agent_finish

### 10.2 OpenAI Swarm (Python, 22k star, 核心 ~300 行)

**极简设计**：Agent = instructions + functions；Handoff = 返回 Agent 实例的函数

**3 个值得借鉴的模式**：
1. **极简 AgentLoop 基底**：tool_calls 循环 <500 行，渐进增强
2. **Handoff 委派**：工具返回另一个 Agent 引用即完成委派，不需复杂状态机
3. **函数签名自动推导 schema**：Go 通过反射 + struct tag 自动生成工具参数描述

### 10.3 CrewAI (Python, 56k star)

**三层模型**：角色(role/goal/backstory) + 任务(description/agent/expected_output/context) + 编排(sequential/hierarchical)

**3 个值得借鉴的模式**：
1. **角色化 Agent 定义**：role/goal/backstory 三件套
2. **任务依赖图**：任务可指定 context（依赖其他任务输出）
3. **Entity Memory**：实体级记忆，自动提取人名/地名/组织

### 10.4 AutoGPT / BabyAGI (Python, 185k star)

**BabyAGI 极简 5 步循环**（140 行）：创建任务 → 排序 → 执行最高优先级 → 结果存向量库 → 生成新任务

**2 个值得借鉴的模式**：
1. **任务驱动循环**：任务创建-排序-执行-反馈的自驱动循环
2. **Agent Protocol**：标准化 Agent HTTP API

## 十一、跨语言记忆系统借鉴（Python 生态）

### 11.1 Mem0 (62.2k star) -- 四层分层记忆

| 层 | 说明 | 生命周期 |
|---|---|---|
| Conversation | 单轮对话即时消息 | 单次响应 |
| Session | 当前任务短期事实（run_id 自动过期） | 分钟到小时 |
| User | 用户绑定长期知识（user_id） | 周到永久 |
| Organizational | 跨 Agent/团队共享 | 全局 |

**5 个值得借鉴的点**：
1. **Single-pass ADD-only 提取**：单次 LLM 调用提取记忆，无 UPDATE/DELETE，只增不改
2. **三路并行检索**：semantic + BM25 + entity 三路并行打分后融合（minibox 当前两路，可扩展第三路）
3. **实体链接增强**：提取实体 → 嵌入 → 跨记忆链接 → 检索时 boost 关联记忆
4. **时序推理排序**：时间感知，处理"现在是什么"vs"过去是什么"
5. **run_id 自动过期**：轻量且实用的短期记忆过期机制

### 11.2 Letta / MemGPT (24k star) -- 五级记忆层次

| 层级 | 在上下文中 | 访问方式 |
|---|---|---|
| Memory Blocks（核心记忆） | ✅ 始终可见 | Agent 自主读写（XML 注入 prompt） |
| Files | 部分 | 只读 |
| Archival Memory | ❌ 按需检索 | 读写（Agent 不可改） |
| Recall Memory | ❌ 按需检索 | 自动生成 |
| External RAG | ❌ 按需检索 | 自定义工具/MCP |

**5 个值得借鉴的点**：
1. **Memory Blocks XML 注入**：核心记忆以 XML 直接注入 prompt，无需检索，始终可见 → minibox 灵魂文件和用户画像用此模式
2. **Agent 自主记忆管理工具**：memory_rethink/replace/insert，让 LLM 自己决定如何维护记忆
3. **Read-only blocks**：防止 Agent 修改重要信息（如灵魂文件）
4. **Shared blocks**：多 Agent 共享同一记忆 block
5. **选择原则**：数据量小且重要 → Memory Blocks；数据量大 → 外部存储 + 检索

### 11.3 Graphiti / Zep (29.4k star) -- 时态知识图谱

- 实体 + 关系 + 事件 + 本体，每条事实有"何时为真"和"何时被取代"的时间窗口
- 三元组 + 溯源（每条事实可追溯原始数据）
- 图遍历检索发现关联信息

**3 个值得借鉴的点**：
1. **时态有效期窗口**：事实有时效性，过期自动降权
2. **溯源**：每条记忆可追溯来源对话
3. **图遍历检索**：通过实体关系发现关联记忆（minibox 未来可选）

### 11.4 RAG 最佳实践汇总

| 实践 | 说明 | 来源 |
|---|---|---|
| 多路并行检索 + RRF 融合 | semantic + BM25 + entity 三路并行 | Mem0 + sage-wiki |
| 两阶段检索 | 粗排 top-200 → 精排重排序 | RAG 通用 |
| 记忆粒度优化 | 独立事实条目优于文档分块 | Mem0 |
| Single-pass 提取 | 单次 LLM 调用提取记忆 | Mem0 |
| 分层存储 | 核心(in-context) / 短期(会话) / 长期(向量) / 外部(MCP) | Letta + Mem0 |

### 12.1 记忆系统重构

**借鉴后**（Mem0 + Letta + sage-wiki 融合）：
```
Layer 0: 核心记忆（XML 注入 prompt，始终可见）[来源: Letta]
         ├── 灵魂文件（read-only block）
         └── 用户画像（可读写 block）

Layer 1: 会话记忆（短期，run_id 自动过期）[来源: Mem0]
         └── 当前对话历史摘要

Layer 2: 长期记忆（FTS5 + 向量 + RRF 融合搜索）[来源: sage-wiki + Mem0]
         ├── BM25 + 向量 RRF 融合
         ├── Single-pass LLM 提取（ADD-only）
         └── 实体链接增强（可选扩展）

Layer 3: MCP 对外暴露（17 个中文工具）[来源: sage-wiki mcp-go]
```

### 12.2 AgentLoop 重构

**借鉴后**（Swarm 极简 + LangGraph State + Eino Aspect）：
```
1. State 初始化（消息历史 + 记忆注入）
2. 循环:
   a. OnStart Aspect（Layer 0 XML + Layer 2 检索注入）[来源: Eino + Letta]
   b. ChatModel.ChatStream -> Iterator 事件流 [来源: Eino]
   c. 事件 -> SSE 推送前端
   d. tool_calls -> PermissionGuard 检查 -> Execute [来源: OpenCode]
      - 返回 Agent -> Handoff 委派 [来源: Swarm]
   e. State 合并（Reducer 模式）[来源: LangGraph]
   f. 守卫检查（MaxIterations / MaxToolCalls）[来源: LangChainGo]
   g. OnToolCall/OnToolResult Aspect [来源: Eino]
3. OnEnd Aspect（Single-pass 记忆提取 + 向量化）[来源: Mem0]
4. Checkpointer 持久化 [来源: LangGraph]
```

### 12.3 工具系统重构

**借鉴后**（Swarm + LangChain + OpenCode）：
```
Tool 定义:
  ├── Name + Description + Schema（struct tag 自动生成）[来源: LangChain]
  ├── Execute(ctx, params) -> Result
  ├── Returns *Agent（非 nil = Handoff 委派）[来源: Swarm]
  └── Permission（allow/ask/deny + glob 匹配）[来源: OpenCode]
```
