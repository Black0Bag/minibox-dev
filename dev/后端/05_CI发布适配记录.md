## 三、Release 发布流程修复

### 1. `.goreleaser.yaml`：移除不存在的 `LICENSE` 引用
- **现象**：GoReleaser 编译 5 个平台二进制全部成功，但归档阶段报 `failed to find files to archive: globbing failed for pattern LICENSE: file does not exist`。
- **根因**：`.goreleaser.yaml` 的 `archives.files` 引用了 `LICENSE`，但新分支 `opencode` 项目**没有 LICENSE 文件**（旧分支才有）。
- **修复**：从 `archives.files` 中移除 `LICENSE`，仅保留 `README.md`。

### 2. Release 触发方式（无需改动，已自洽）
- `.github/workflows/release.yml` 触发条件为 `push: tags: v*`，无分支绑定；在新分支打 tag 即可触发。
- `main: ./cmd/minibox` 入口存在，ldflags 注入的 `main.version/commit/date` 变量已在 `cmd/minibox/main.go` 定义，完全匹配。

## 四、CI 流水线修复

### 3. Go 版本升级：`1.26.5` → `1.26.6`
- **现象**：`依赖安全扫描`(govulncheck) job 失败，报 Go 标准库 5 个漏洞（GO-2026-5972、GO-2026-5026 等）。
- **根因**：Go 1.26.5 的标准库存在漏洞，修复版为 **1.26.6**。
- **修复**：
  - `go.mod` 的 `go` 指令 → `1.26.6`
  - `.github/workflows/ci.yml` 的 `go-version` → `1.26.6`
  - `.github/workflows/release.yml` 的 `go-version` → `1.26.6`

### 4. golangci-lint-action 升级：`@v6` → `@v9`
- **现象**：`静态检查` job 失败，报 `the Go language version (go1.24) used to build golangci-lint is lower than the targeted Go version (1.26)`。
- **根因**：`golangci-lint-action@v6` 的 `version: latest` 解析到旧版 golangci-lint v1.64.8（用 go1.24 构建），无法解析 go1.26 代码。
- **修复**：`golangci/golangci-lint-action@v6` → **`@v9`**（v9 才支持 golangci-lint v2 与 go1.26）。

### 5. golangci-lint 版本固定：`v2.12.2`
- **现象**：升级 action 到 v9 前，显式指定 `v2.12.2` 时 v6 action 报 `invalid version string 'v2.12.2', golangci-lint v2 is not supported by golangci-lint-action v6`。
- **修复**：配合 action v9，固定 `version: v2.12.2`（v2 用 go1.26 构建，与项目匹配）。

### 6. `.golangci.yml` 迁移到 v2 配置格式
- 旧 v1 格式在新版 golangci-lint v2 下不兼容。
- **修复**：改为 v2 格式（顶层 `version: "2"`、`linters.enable` 等），并显式声明语言版本。

- **CI 触发**：`push` 到 `opencode` 分支 + PR

## 七、版本管理方案（SemVer）

采用语义化版本管理，从 `v0.0.1-beta` 起步：

| 变更类型 | 版本递增 | 示例 |
|---|---|---|
| 修复 bug | 补丁 +1 | `v0.0.1` → `v0.0.2` |
| 新增功能 | 次版本 +1（0.x 阶段） | `v0.0.2` → `v0.1.0` |
| 破坏性变更 | 主版本 +1 | `v0.x` → `v1.0.0` |
| 预发布 | 追加 `-alpha/-beta/-rc` | `v0.0.1-beta` |

## 八、遇到的问题与踩坑记录

1. **GoReleaser 归档缺文件**：release 配置文件引用了项目里不存在的文件（LICENSE）会导致发布失败，且是在编译成功后才报错，需检查 `archives.files` 与仓库实际文件一致。
2. **golangci-lint 与 Go 版本不匹配**：golangci-lint 必须用 `>= go.mod 目标版本` 的 Go 构建，否则无法解析新语法；且 action 版本（v6/v7/v9）对 golangci v1/v2 支持不同，`version: latest` 不一定可靠，建议显式固定。
3. **govulncheck 对标准库漏洞敏感**：Go 补丁版本升级后，标准库漏洞通常只需同步升级 Go 版本即可修复。
4. **本地环境无法验证**：proot 沙箱下载 Go 1.26 二进制会段错误，也无法运行 goreleaser，故所有验证都依赖 GitHub Actions 真实运行反馈，采取"触发 → 看失败 → 修复 → 再触发"的迭代方式。
