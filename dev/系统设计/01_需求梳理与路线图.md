## 1. 一句话定位

> **一个以 Go 后端为「中枢大脑」、以安卓 APP 为「眼耳口手」的私有化强 Agent 系统：**
> 后端通过 LLM 云端算力在本地执行长程任务（to-do-list + subagent 并行），
> 以「知识库 = 唯一记忆」实现自我进化与用户蒸馏；
> 前端 APP 作为分离大前端，通过协议完整承接后端能力，并用无障碍 + Shizuku 把手机变成后端可操控的终端，用内嵌浏览器补齐后端的网页能力。
>
> **项目将开源发布（GitHub）**，面向未知设备环境，用户预期终身使用。

## 3. 服务端需求拆解（Go 中枢网关）

### 3.1 Agent 核心引擎（已有基础，重构优化）
| 需求 | 现状 | 差距 |
|---|---|---|
| 多模式 Agent（Assistant/Loop/Supervisor） | ✅ 已有 | 需把 Supervisor 升级为真正的 to-do-list 长程驱动器 |
| to-do-list 模式按计划逐步执行 | ✅ 内置工具 todo_write | 需补「计划校验/步骤回滚/中断续跑」 |
| subagent 并行执行 | ⚠️ 仅规划 | 并发上限/隔离/结果聚合 → **全部做成用户自定义设置项** |
| 多供应商 LLM + 降级链 | ✅ 已有 | 保持；开源后需把供应商配置做成向导式 |

> 决策 C1：**继续自研演进**，不做大框架引入；因用户认为现有优化方式不够清晰明确，本次以「重新梳理需求 → 重构优化」为方向，本文件即梳理产物。

### 3.2 logme 文件夹足迹系统（新，代码级写死规则）
- 触发点：agent 对某文件夹做「读取/写入/遍历」前，先检索该文件夹是否存在 `logme` 文档。
- 规则：
  1. 无 `logme` → 自动创建，写入「文件夹用途区 + 本次操作记录」。
  2. 有 `logme` → 将本次操作（时间、操作者、动作、结果摘要）以追加方式写入末尾，**每条带时间标签**。
  3. **写死保护**：agent 对已有文本**只允许追加、禁止删改**；删除/修改已有内容仅限**用户授权**（显式授权 + 审计留痕）。
- **文件夹语义区**（决策 D1：两者都要）：
  - 每个 logme 头部固定「文件夹用途 / 操作技巧 / 注意事项」区。
  - agent 二次进入文件夹时，**第一时间读取该区**，避免重复分析，直接获得此前沉淀的经验。
- 设计要点：
  - 做成 Go 侧 `fsutil` 统一 wrapper（所有文件操作必经），**代码级 enforce，不靠 prompt 约定**。
  - 格式：纯文本分段 + 时间标签，人机可读，`## YYYY-MM-DD HH:MM 操作者: 动作`。
  - 决策 D3：**minibox 项目不采用「任务接力追踪文件」机制**（那是外部环境的妥协临时方案），本项目的任务状态/留痕统一由 logme + 知识库承载。

### 3.3 知识库系统 = agent 唯一记忆系统（核心，铁律）
> 决策 B1（铁律）：**agent 的所有信息一律以知识库方式存放**——包括本应文本存放的记忆/SOUL/画像等，全部入库，便于搜索/调用/编辑/编译。分层是组织方式，知识库是唯一存储容器。

- **编译管道**（LLM 驱动，异步任务队列）：
  - 网址 → 自动进入网站抓取 → 提炼有效信息 → 页面索引（标题/摘要/关键词/分类/时间）。
  - 文本 → 提炼知识要点 → 结构化入库。
  - 图片 → 视觉模型提炼 → 索引 + 关键词 + 缩略图。
- **记忆分层**（入库的组织视图）：
  - 短期记忆（会话级，可压缩） / 长期记忆（事实型） / SOUL 灵魂（行为规则/身份） / 用户画像（蒸馏产物）。
- **自我进化**（决策 B3：全部做成用户自定义设置项）：
  - 精炼提纯触发：每日定时 / 交互量阈值 / 手动 → 用户可配。
  - 蒸馏策略：从用户历史交互提炼偏好、习惯、爱好 → 更新用户画像，让 agent 越来越懂用户。
  - Skill 沉淀：从成功工作流提炼标准化流程 → 生成 skill → 同类需求直接调取加速。
- **存储选型**（决策 B2）：采用**已验证方案** —— `research/go-sqlite-fts5-vector-search`（SQLite + FTS5 + 向量检索），单文件、跨平台、可备份。
- **对外**：通过 MCP 服务接口暴露，供其他 agent 调取。

### 3.4 自动化执行与心跳（新）
- 「主动心跳信号」：捕捉用户要求监控的任务（盯网页变化 / 等条件满足 / 每日报告），到点自动触发 agent 执行。
- 决策 F2：心跳任务**可以主动操作**（发消息/操作设备），但**必须绑定用户预先设定的需求**——即任务的行为边界由用户在创建时定义，agent 不得越界。
- 调度引擎：后端内置调度中枢（对齐 schedule/alarm/calendar 三分类思想），触发与结果写入知识库。

### 3.5 服务器性能实时监控（新）
- 实时采集落地主机 CPU/内存/磁盘/网络/进程指标，提供 REST API 供前端展示。
- 开源后需做「资源自适应」：低配设备自动降级（禁用向量库重功能、限制 subagent 并发）。

## 4. 安卓端需求拆解（分离大前端）

### 4.1 协议层（已有 WS :8086 + SSE，决策 E2：以稳定为纲）
- REST + WebSocket 长连接 + SSE 事件流；协议不限形式，**稳定性第一**：断线重连、心跳保活、消息确认、版本协商。
- 设备代理通道：WS method 前缀「设备_*」「浏览器_*」。

### 4.2 UI 多组件（后端 API 的分离前端，决策 E1：继续 Flutter）
| 组件 | 对应后端能力 |
|---|---|
| 对话/任务控制页 | Agent Loop、to-do-list 状态、subagent 进度 |
| 知识库浏览器/编辑器 | 记忆分层查看、条目编辑、编译管道任务管理 |
| 设备控制面板 | 设备代理 Hub（配对/能力开关/权限/审计） |
| 性能监控页 | 服务器监控 API |
| 设置页 | LLM 供应商、模型、进化策略、安全策略、subagent 配额 |

### 4.3 语音层（决策 E3：预留接口）
- 当前未找到免费模型 API → **预留**：优先 Android 本地 TTS（免费兜底），模型 API 接口位保留，后续接入。

### 4.4 设备控制（方案已定，实施推进）
- 无障碍 + Shizuku 双通道 → 完全控制手机 = 后端「眼耳口手」。
- 安全框架：配对码、权限分级、危险操作策略（决策 F1：**逐次确认与白名单自动放行并存，用户可配**）、截图像素级模糊、TLS、失控保护。

### 4.5 内嵌浏览器代理（方案已定，补 tab 隔离）
- 后端硬件限制无法集成浏览器 → 浏览器放 APP，供 agent 使用。
- **代码级规范**：每个 subagent 新建独立标签页，互不抢占；subagent 结束 → tab 释放（可配保留）。
- tab 白名单限制、Cookie/登录态按 tab 隔离、subagent↔tab 生命周期绑定。

### 4.6 桌面小组件 + 记事本编译系统（新）
- 记事本：独立条目记录，每条带「状态」字段（待编译/编译中/已编译/失败）。
- 触发（决策 E4）：**用户为条目设定时间**，到点 agent 后台编译 → 理解内容 → 若是想法 → 静默分析 → 产出可行性参考 → **结果存入知识库** → 状态置「已编译」。
- 桌面小组件：快捷入口 + 条目状态展示。

### 4.7 PC 端（占位待定）
- 同一协议层可被 PC 前端复用（Web/Electron），本轮不展开。

## 8. 风险与边界

1. **开源带来的安全压力**：设备控制（Shizuku+无障碍）是高权限能力，开源后默认配置必须安全（首次启动向导、最小权限、密钥本地化不硬编码、审计日志）。
2. **跨平台资源差异**：路由器 vs 云服务器性能差距巨大 → 资源自适应 + 优雅降级是硬需求。
3. **终身使用的数据资产**：知识库是用户终身积累 → 备份/迁移/导出是第一公民功能，格式稳定 + schema 版本管理。
4. **logme 强制留痕的开销**：IO 与 token 成本上升 → 设计上要轻量（纯文本追加），wrapper 内部无感知执行。
5. **知识库膨胀**：编译管道需节流（去重、配额、可配置策略）。
6. **LLM 成本**：蒸馏/编译/静默分析持续消耗 token → 成本监控 + 低配模型跑编译、强模型跑决策的策略。
7. **多端一致性**：后端升级 vs APP 零更新 → 协议版本协商。

## 9. 术语表
- **中枢大脑**：Go 后端 minibox，跨平台部署。
- **眼耳口手**：安卓 APP 对后端的感知（截屏/传感器）、输入（点击/输入）、输出（语音/通知）、操作（Shizuku/无障碍）能力。
- **logme**：文件夹级操作留痕 + 语义沉淀文档，代码级写死规则（agent 只增不改，用户授权例外）。
- **编译管道**：把网址/文本/图片等原始输入，经 LLM 处理为结构化知识条目的异步流程。
- **蒸馏**：从用户历史交互中提炼偏好/画像，让 agent 更懂用户。
- **设备代理**：APP 与后端之间的 WS 通道，method 前缀「设备_*」「浏览器_*」。
- **任务追踪文件**：外部环境的妥协临时方案，本项目不采用（由 logme + 知识库替代）。

    |---|---|---|
