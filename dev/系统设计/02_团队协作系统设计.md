# 团队协作系统设计（当前版）

## 概念

团队协作把复杂 Agent 任务组织为“服务型公司”：用户是甲方，主会话是前台，专业团队负责分诊、讨论和结案。

## 当前后端实现

- 三种模式：聊天、Plan-Build、项目。
- 团队目录和关键词分诊。
- 角色卡、运行时成员、层级上限和工具白名单。
- IPP 讨论：独立提案、批评、组长裁决、轮次上限。
- HR 增派审批、预警和信任档案。
- Coordinator：Triage → StartProject → RunDiscussion → Conclude → Staffing。
- REST：团队列表、分诊、项目启动、讨论、结案、增派。

## 前端首版职责

- 展示团队目录与分诊结果。
- 启动项目并展示项目问题锁、团队和讨论提案。
- 显示结案结果和增派预警。
- 不在前端重做团队调度或信任计算。

## 当前契约限制

- 项目状态主要在内存中，后端重启后的恢复语义尚未冻结。
- `TaskDependency` 需要稳定 JSON tag 后才能作为 Android 首版可靠 DTO。
- 团队 LLM 输出受外部供应商可用性影响，错误必须单独显示。

## 安全边界

团队不能绕过统一工具权限链、设备护栏或用户审批。增加 Agent 层级不等于增加系统权限；所有实际副作用仍由工具元数据和审批策略控制。
