# Android 设备代理方案（当前版）

## 定位

Android APP 通过 WebSocket JSON-RPC 连接 Go 后端，向后端提供手机侧“眼耳口手”能力。后端做决策、权限和审计，前端只执行经过验证的命令。

## 通信流程

```text
WS connect(auth, protocol=1.0)
  → device/hello 上报 ID、机型、Android、能力
  → heartbeat.ping/pong
  → 后端发送带唯一 id 的设备命令
  → Android 校验能力/权限/审批并执行
  → 用相同 id 返回 result 或 error
```

真实外层设备 hello 使用 JSON-RPC method=`device`，params 中再包含内层 `method=hello` 和 `params`。

## 能力分类

- 眼：截屏、UI 层级、通知列表、设备信息、前台应用。
- 手：点击、滑动、长按、输入、按键、打开应用、滚动查找、剪贴板写入。
- 口：朗读、提示、通知。
- 耳：听写、监听。

具体名称和风险以后端 `/api/v1/tools/` 返回为准；不要在 Android 中独立维护第二份风险表。

## Android 组件边界

- `DeviceConnectionService`：前台服务、WS 生命周期、心跳和重连。
- `DeviceRpcClient`：单读循环、pending map、JSON-RPC 编解码。
- `CapabilityRegistry`：动态能力与 Android 权限状态。
- `DeviceCommandDispatcher`：命令白名单、参数校验和执行器路由。
- `DeviceExecutor`：Accessibility/MediaProjection/TTS/STT 等具体执行。
- `DeviceAuditStore`：脱敏本地审计摘要。

## 安全要求

1. 设备 token 放在 Keystore 支持的安全存储中。
2. 每条命令检查目标设备 ID、method、参数、能力、系统权限和审批状态。
3. 危险动作默认拒绝；连接异常、超时或无法确认时不执行。
4. 截图、UI 文本、通知、剪贴板和听写内容不写普通日志。
5. 急停要能关闭连接并取消 pending/正在执行的任务。
6. 真机测试按能力单独授权，不做一键全能力测试。

## 当前限制

- 后端模拟设备往返已验证，真实 Android 执行器未开发。
- REST 通用认证和交互式审批提交 API 尚待后端补齐。
- browser 方法族当前不是完整浏览器代理实现，首版设备代理不要声称支持完整浏览器自动化。
