# minibox 2.0「设备代理」方案：前端 APP 作为后端的眼耳口手

> 目标：让后端 Agent 通过前端 APP 对手机进行操控（屏幕识别、点击、滑动、输入、朗读、听写、通知读取），实现"自动操作手机"
> 可行性结论：**完全可行**，小万 OmniBot 的 vlm_task 已验证 Android 端截屏+无障碍操控能力，本方案将其协议化、前后端分离

## 三、通信协议设计（WebSocket + JSON-RPC 2.0）

### 3.1 连接与会话

```
前端 APP ──► 后端 :8086/device/ws?device_id=xxx&token=配对令牌
```

- **心跳**：前端每 15s 发 `{"type":"ping"}`，后端回 `{"type":"pong"}`；3 次未响应判离线
- **配对**：首次连接时 APP 显示 6 位配对码，用户在后端 WebUI 输入确认 → 绑定设备
- **多设备**：后端 Hub 支持多设备注册，按 `device_id` 路由

### 3.2 消息格式

```jsonc
// 后端 → 前端：命令下发
{
  "type": "command",
  "id": "cmd_8f3a2b1c",          // 命令唯一 ID
  "method": "设备_点击",          // 能力名（对应 MCP 工具）
  "params": { "x": 540, "y": 1200, "duration_ms": 80 }
}

// 前端 → 后端：命令结果
{
  "type": "result",
  "id": "cmd_8f3a2b1c",
  "ok": true,
  "data": { "screen": "base64_截屏数据" }   // 截屏/层级等数据回传
}

// 前端 → 后端：主动事件（通知/来电/传感器/授权状态变化）
{
  "type": "event",
  "event": "notification",
  "data": { "pkg": "com.tencent.mm", "title": "新消息", "text": "..." }
}

// 前端 → 后端：能力/权限状态上报（连接即上报）
{
  "type": "hello",
  "device": { "id": "mi10", "model": "Xiaomi Mi 10", "android": "14" },
  "capabilities": ["截屏", "界面层级", "点击", "滑动", "输入文字", "朗读", "听写"],
  "permissions": { "accessibility": true, "mediaProjection": false, "notification": true }
}
```

### 3.3 关键交互流程（自动操作手机）

```
用户（后端 WebUI 或语音）："帮我把微信里小王发的地址存到备忘录"

后端 Agent：
1. 调 设备_截屏 → 前端返回当前屏幕 base64
2. 视觉 LLM 分析截图 → 识别出微信图标 → 返回坐标
3. 调 设备_点击 {x,y} → 前端执行点击
4. 再 设备_截屏 → 确认进入微信 → 视觉分析找到"小王"对话
5. 循环：点击 → 截屏 → 分析 → 点击 ...（直到到达目标页面）
6. 调 设备_输入文字 → 前端输入"已收到地址"
7. 调 设备_点击 → 发送
8. 调 设备_朗读 → 前端 TTS 播报"已完成"

全流程：Agent 决策 + 视觉模型识别在后端，执行动作在前端，每一步截图回传。
```

### MCP 工具注册示例（Go）

```go
s.srv.AddTool(mcp.NewTool("设备_截屏",
    mcp.WithDescription("截取手机当前屏幕，返回 base64 PNG 图像，供视觉识别使用"),

s.srv.AddTool(mcp.NewTool("设备_界面层级",
    mcp.WithDescription("获取当前界面的无障碍节点树（类似 Appium page source），含文本/坐标/可点击性"),
```

### 权限引导（设置页新增）

```
设备代理
├── 连接状态（已连接/离线/延迟）
├── 配对管理（配对码/设备ID/解绑）
├── 能力开关
│   ├── 视觉（截屏）        [需要 MediaProjection 授权]
│   ├── 操作（点击/滑动/输入）[需要 无障碍服务]
│   ├── 通知读取             [需要 通知使用权]
│   ├── 语音听写             [需要 麦克风权限]
│   └── 语音朗读             [无需额外权限]
├── 安全设置
│   ├── 危险操作需确认（发送消息/删除/支付类，逐次弹窗）
│   ├── 仅局域网连接开关
│   └── 操作审计日志（谁在什么时间操控了手机）
└── 测试面板（手动截图/取 UI 层级/试听朗读）
```

## 六、安全设计（重要）

| 风险 | 缓解措施 |
|---|---|
| 远程被控 | 首次配对码确认 + 设备绑定；支持随时"急停"（断开并冻结） |
| 敏感操作 | 权限分级：视觉只读；操作类需 APP 内开启；危险操作逐次 HITL 确认弹窗 |
| 隐私泄露 | 截图默认降采样 + 可配置模糊敏感区域（通知/密码框遮挡） |
| 密钥安全 | 配对令牌存 Keystore；传输走 TLS（wss） |
| 审计 | 所有命令/结果落本地+后端双份日志，可回溯 |
| 失控保护 | 后端心跳超时自动断开；APP 前台运行时才接受操控（可配置） |

## 七、与小万 vlm_task 对比（差异化优势）

| 维度 | 小万 vlm_task（本地） | minibox 设备代理（分离式） |
|---|---|---|
| 视觉模型 | 手机本地小模型 | 后端任意强模型（qwen-vl/gpt-4o/glm-4v） |
| 决策能力 | 本地规则 | 完整 Agent + 工具 + 记忆 |
| 算力 | 手机受限 | 服务器无限 |
| 多设备 | 单手机 | 多手机统一管理（后端 Hub） |
| 跨设备协同 | 无 | A 机截图 → B 机操作 可编排 |
| 可维护性 | 升级要发版 | 后端改逻辑即生效，APP 零更新 |

## 八、实施路径

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **P0 链路打通** | 后端 device 网关（WS Hub + 配对）+ MCP 设备工具骨架 + 前端 WS 客户端 + 截屏/点击两项能力 | 证明"截屏→分析→点击"闭环 |
| **P1 能力补全** | UI 层级/滑动/输入/按键/打开应用/朗读 + 无障碍完整接入 + 权限引导页 | P0 |
| **P2 智能决策** | 视觉 LLM 接入 + Agent 自动循环（截图→决策→动作→验证）+ HITL 确认 | P1 |
| **P3 体验完善** | 通知监听/听写/多设备/审计面板/安全加固 | P2 |
