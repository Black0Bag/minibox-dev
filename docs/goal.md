# 项目总目标（Goal）

## 项目背景

- 业务场景：私有化强 Agent 系统，Go 后端作为中枢大脑，Android APP 作为用户界面和设备侧能力代理。
- 目标用户：个人自用，追求极简美观流畅的私有化 AI Agent 系统。

## 总目标

在私有化、可审计和默认安全的前提下，提供可以长期维护的强 Agent 系统。保持三仓库职责清晰、事实一致，后端深度优化打磨稳定后，再基于稳定后端进行前端开发。

## 成功标准

### 功能成功标准

- 后端代码/测试/文档可验证，CI 全绿。
- 后端技术债清理完毕，架构打磨稳定。
- 前端基于稳定后端契约进行开发，不直接访问 SQLite。
- Dev 只保留当前产品结论，无历史噪音。
- 测试目录只保留最后稳定实例和唯一私密配置。

### 质量成功标准

- `go test -count=1 ./...`、`go vet ./...` 和构建通过。
- 关键协议覆盖成功、失败、断线或重试场景。
- 配置、日志、测试报告和文档不泄漏凭据或用户数据。
- 版本管理：VERSION 文件唯一源 + CI 强制校验 + 已发布 Tag/Release 不移动不覆盖不删除。

## 范围边界（做 / 不做）

- 做：产品决策、前后端边界、阶段路线、验收摘要、版本管理、文档治理、后端深度优化、前端基于稳定后端开发。
- 不做：在 Dev 仓库复制源码、测试产物、凭据或完整历史日志；前端在后端稳定前启动。

## 约束条件

- 技术约束：Go 模块化单体 + SQLite + REST/SSE/WebSocket；Android Kotlin + Jetpack Compose + Material 3。
- 安全约束：本地凭据与源码、文档、日志隔离；设备写操作 fail-closed。
- 协作约束：后端协议变化必须同步更新前端交接文档。
- 版本约束：VERSION 文件唯一源，CI 强制版本一致性校验，已发布 Tag/Release 不可变。
