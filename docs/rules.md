# 编码与文档规则（Rules）

## 默认规则（创建即生效）

- 事实以当前源码、测试和接口契约为准。
- Dev 文档只保留结论，不记录每次命令和中间失败流水。
- 不复制真实配置或敏感日志。
- 版本管理：根目录 `VERSION` 文件是唯一版本源；`git tag v{VERSION}` 触发发布；CI 强制校验 VERSION 与 Tag 一致性；已发布 Tag/Release 不移动、不覆盖、不删除。

## 命名规范

- 中文文档使用清晰主题名；Android/Go 标识遵循各语言标准。
- REST JSON 字段使用 lower_snake_case。
- 仓库和文档名称表达职责，避免 final/fixed 等临时后缀扩散。

## 代码风格

- Go 使用 gofmt；Compose 使用状态提升和单向数据流。
- Navigation 3 使用可序列化 `NavKey` 和可保存 back stack。
- 编码实现遵循最小实现阶梯：能复用不重写、能一行不写多行、不砍校验/安全/错误处理；非平凡逻辑留 1 个可运行检查。

## 错误处理

- HTTP 200 不等于业务成功；前端解析 Problem Details。
- SSE/WS 必须有重连、超时、序号/ID 归属和错误状态。

## 日志与注释

- 记录关联 ID 和错误类型，不记录 Key、auth、屏幕/剪贴板内容。

## 安全与隐私

- API Key、Token、设备凭据进入受控本地存储，不进入 Git。
- 升级、回滚、设备写操作必须审批并审计。
- 测试配置和运行数据不得进入 Git 或公共文档。

## 测试与回归要求

- 后端变更运行 test/vet/build；前端覆盖 reducer、repository、导航状态和关键 UI 测试。
- 后端运行完整门禁；前端按阶段建立 fixture/UI/真机分项测试。

## 禁止事项（反模式）

- 禁止从已删除历史文档恢复过时架构。
- 禁止前端直连后端 SQLite。
- 禁止跳过文档治理直接做后端优化或前端开发。
- 禁止前端在后端 v0.2.1 发布前启动。
- 禁止已发布 Tag/Release 移动、覆盖或删除。
- 禁止 VERSION 文件与 git tag 不一致（CI 会强制失败）。
- 禁止跳过 CI 检查直接合并到主分支。
