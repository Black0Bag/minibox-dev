# 编码与文档规则（Rules）

## 默认规则（创建即生效）

- 事实以当前源码、测试和接口契约为准。
- Dev 文档只保留结论，不记录每次命令和中间失败流水。
- 不复制真实配置或敏感日志。

## 命名规范

- 中文文档使用清晰主题名；Android/Go 标识遵循各语言标准。
- REST JSON 字段使用 lower_snake_case。

## 代码风格

- Go 使用 gofmt；Compose 使用状态提升和单向数据流。
- Navigation 3 使用可序列化 `NavKey` 和可保存 back stack。

## 错误处理

- HTTP 200 不等于业务成功；前端解析 Problem Details。
- SSE/WS 必须有重连、超时、序号/ID 归属和错误状态。

## 日志与注释

- 记录关联 ID 和错误类型，不记录 Key、auth、屏幕/剪贴板内容。

## 安全与隐私

- API Key、Token、设备凭据进入受控本地存储，不进入 Git。
- 升级、回滚、设备写操作必须审批并审计。

## 测试与回归要求

- 后端变更运行 test/vet/build；前端覆盖 reducer、repository、导航状态和关键 UI 测试。

## 禁止事项（反模式）

- 禁止从已删除历史文档恢复过时架构。
- 禁止前端直连后端 SQLite。
- 禁止在后端尚无提交 API 时伪造可用审批 UI（Agent 工具审批 API 已于
  2026-09-02 就绪，可实现真实按钮；其余无契约功能仍适用本条）。
