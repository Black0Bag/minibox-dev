# 项目架构（Structure）

## 目录结构

```text
minibox-dev/
├── README.md
├── docs/                       工作流核心文档
└── dev/
    ├── 01_项目总路线图.md
    ├── 02_后端开发路线图.md
    ├── 03_前端开发路线图.md
    ├── 05_后端深度验证与再验收.md
    ├── 前端/                    前端基准与能力参考
    └── 系统设计/                团队和设备概念
```

## 模块划分

- 总路线图：产品定位、边界和阶段状态。
- 后端路线图：维护边界和已知限制。
- 前端路线图：Android 可执行顺序。
- 系统设计：跨前后端概念，不重复源码 API。

## 数据流/调用关系

后端 `docs/`（协议事实）→ Dev 路线图（产品排序）→ Android 仓库（实现与测试）。

## 依赖与外部接口

- 代码事实来自 `minibox`。
- 前端实现位于 `minibox-android`。
- 本仓库没有运行时依赖或凭据。

## 关键入口文件

- `README.md`
- `dev/01_项目总路线图.md`
- `dev/03_前端开发路线图.md`

## 高风险模块

- 文档漂移：旧 API/选型被误当当前事实。
- 隐私：测试配置或日志被复制进文档。
- 产品承诺：把预留方向写成已实现能力。
